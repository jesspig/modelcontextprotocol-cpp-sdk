# 2026-09-15 更新日志

## 2026-09-15-00 — CI 与 conformance 修复：URL elicitation 竞态、SSE keepalive、就绪探测

- **服务端 URL elicitation 注册先于发送**（[McpServer.cpp:472-489](../../src/server/McpServer.cpp)）：`ElicitUrl` 把 `pending_url_elicitations_` 注册移到 `SendRequest` 之前——complete 通知可能先于注册到达被静默丢弃、promise 永不完成；`SendRequest` 抛异常时清理已注册条目后 rethrow
- **超时消息区分与未知 id 日志**（[McpServer.cpp:497-523](../../src/server/McpServer.cpp)）：`url elicitation timed out (no response)`（请求无应答）与 `(no complete notification)`（响应已到但 complete 未到）分别报错、保留前缀；complete 通知携带未知 `elicitationId` 时丢弃并 `MCP_LOG(Warning, ...)`（原为静默 return）
- **客户端 complete 先于响应**（[McpClient.cpp:545-557](../../src/client/McpClient.cpp)）：URL elicitation 处理先发 `notifications/elicitation/complete`、再 `p.set_value` 提交响应；通知发送异常被捕获仅记 Error，不影响响应提交
- **SSE keepalive 忙循环修复恢复（f5c7262）**（[HttpServerImpl.cpp:840](../../src/http/HttpServerImpl.cpp)）：`KeepAliveLoop` 的 `wait_for` 谓词恢复为仅 `!running_.load()`——旧谓词 `!running_ || !sse_clients_.empty()` 使有 SSE 客户端时恒真、`wait_for` 立即返回，keepalive 线程忙循环烧 CPU；该修复曾以 f5c7262（`fix(网络栈): 修复 SSE keepalive 谓词反转忙循环致 macOS CI 超时`）提交，但该提交不在当前分支历史（无分支包含，dangling），本轮恢复。现每轮睡满 `sse_keep_alive_ms` 后广播 ping，仅 `Stop()`（`running_` 置 false + `notify_all`）唤醒退出
- **conformance CI 配置**（[.github/workflows/conformance.yml](../../.github/workflows/conformance.yml)、[run-conformance.sh](../../scripts/run-conformance.sh)）：server/client 双 job `node-version` 20 → 22（referee 依赖 Node 22+ 的 `fs.globSync`）；server 就绪探测由 `curl -s --max-time 2 GET /mcp` 改为 `probe_ready()` POST `initialize`——GET 会建立 SSE 长流使 `--max-time 2` 必然超时（退出码 28）
- **验证**：`Phase2InMemoryElicitFixture.UrlElicitationRoundTrip` `--gtest_repeat=100` 零失败；相关 19 用例通过（含 `SseKeepAliveFrames`）；全量 ctest 578/578 通过；本地 conformance-server 实测 POST `initialize` 0.15s 返回 HTTP 200（旧 GET 探测 curl 退出码 28）

## 2026-09-15-06 — conformance client sse-retry：退避睡眠语义恢复与 SSE 空 data 解析修复

- **客户端退避睡眠语义颠倒恢复（丢失提交 8363d75 等价恢复）**（[StreamableHttpClientTransport.cpp:142-149](../../src/http/StreamableHttpClientTransport.cpp)）：`SleepInterruptibly` 谓词由 `!stop.load()` 改为 `running.load()`（参数 `stop` → `running`，调用点传 `running_`）——原实现运行中 `running_=true` 时 `!stop` 恒假、退避睡眠从不生效，Close 后置 false 反而睡满；修复后运行中睡满退避时长、`Close()` 可打断。与未进入任何分支历史的 dangling 提交 8363d75（`fix(网络栈): 修复客户端退避睡眠语义颠倒并补投 SSE 首连前丢失的广播`）中该文件的改动逐字一致（含注释）
- **SSE 空 data 解析缺陷**（[StreamableHttpClientTransport.cpp:108-113](../../src/http/StreamableHttpClientTransport.cpp)）：`data:` 冒号后仅空白时，原实现 `find_first_not_of` 返回 `npos` 后保留原值（如 `" "`），`result.data` 非空 → `DeserializeMessage` 失败 → `DispatchSseBlock` 报 Error `HTTP SSE block parse failed`；referee sse-retry 的 priming 事件 `id`/`retry`/`data:`（空 data）命中该路径。现改为 `npos` 时产出空串，`DispatchSseBlock` 开头 `if (parsed.data.empty()) return;` 静默忽略
- **client 基线条目恢复 `sse-retry`**（[baseline.yaml:50-55](../../tests/conformance/baseline.yaml)，client 段 36 → 37 条）：归因——server 关流后 client 未等待 retry 字段声明的 500ms 即重连（实测 -70ms，要求 >=450ms 且 <=1000ms）；另有 WARNING/SHOULD：重连未携带 Last-Event-ID 头。条目注明"实现 retry 等待与 Last-Event-ID 后删除本条目"（届时 runner 以过期条目报错）；该条目曾存在于历史 baseline（对照 `git show f5c7262:tests/conformance/baseline.yaml`，当时 retry 计时实测为 -112ms）
- **验证**（本地 Node 24 + referee 0.2.0-alpha.11）：client leg `Baseline check passed` exit 0（sse-retry 命中基线条目）；server leg exit 0（65 passed / 2 failed 均在基线）；全量 ctest 578/578 通过
