- 2026-11-18-14 — Windows 任务存储压缩中毒修复，`feature/task-store-compaction-fix`（基于 `f72bcfd`）。**根因**：[src/server/FileTaskStore.cpp](../../src/server/FileTaskStore.cpp) 的 `AppendRecord` 在自身 `std::ofstream` 仍打开时调用 `CompactLocked`；Windows UCRT 的 `ofstream` 以 `FILE_SHARE_READ | FILE_SHARE_WRITE` 打开（无 `FILE_SHARE_DELETE`），`WriteAtomic` 的 `MoveFileEx(..., MOVEFILE_REPLACE_EXISTING)` 被共享约束拒绝，压缩返回 false → `AppendRecord` 返回 false → 所有写方法回滚内存并抛 `McpError(InternalError)`，且下一次追加仍越过阈值重试失败，任务存储会话永久中毒。**修复**：把追加 `ofstream` 收进独立作用域，`flush`/`good` 检查后关闭句柄再计数与压缩；压缩改为 best-effort——`CompactLocked` 失败只记 Error 日志并把 `pending_records_` 归零，`AppendRecord` 仍返回 true，只有追加本身（打开/写入/flush）失败才回滚抛错（与 [FileEventStore.cpp](../../src/http/FileEventStore.cpp) 的“先关句柄再 rewrite”一致）。**测试**：[tests/unit/FileTaskStoreTests.cpp](../../tests/unit/FileTaskStoreTests.cpp) 新增 `AutomaticCompactionAcrossThresholdKeepsWritesSucceeding`（200 次写触发多轮压缩、文件行数受限、重载 owner 为末值）与 Windows 专属 `CompactionFailureKeepsSubsequentWritesSucceeding`（`CreateFileW` 占住目标文件使 rename 失败，断言 200 次写全部成功、文件 201 行、释放句柄后重载 owner 正确；非 Windows 不编译）；先以原实现复跑两例，均在 `task store: failed to persist task task-1` 处失败，修复后 `mcp-task-store-tests` 26/26 通过。**文档**：[docs/zh/reference/process-and-storage.md](../../docs/zh/reference/process-and-storage.md) 与英文镜像、[wiki/classes/file-task-store.md](../classes/file-task-store.md)、[wiki/concepts/storage.md](../concepts/storage.md)、[wiki/tests.md](../tests.md)、[wiki/index.md](../index.md)、[wiki/concepts/tier1-parity.md](../concepts/tier1-parity.md)、[AGENTS.md](../../AGENTS.md) 基线与中英安装页计数同步。**验证**：Windows 全量 `ctest --preset debug` **1021/1021 全绿**（363.11s，注册 1021 = 静态 1032 − 11 条件编译）；静态 **1032 用例 / 4887 断言**（同批按实测把 `mcp-wire-codec-tests` 的历史断言数 443 校正为 446，非本轮新增）；`check-parity` 59 对标题差异 0、`check-api-symbols` 命中 210 / 未命中 0。**环境偏差**：worktree 新链接的 `mcp-uri-template-tests.exe` 在本机被执行策略拒绝（Access denied，链接与 gtest 输出均正常）；全量运行改用主仓库同一提交 `f72bcfd` 的既有二进制完成该 21 个用例，本轮源码与测试改动均不涉及该目标。未推送、未开 PR。
