# 2026-09-11 更新日志

## 2026-09-11-04 — _meta 线上位置修正：JSON 顶层 → params._meta

- 请求/通知的 `_meta` 线上位置从 JSON 顶层改为 `params._meta`（对齐官方规范与 TS 服务器）；序列化层（`src/core/JsonRpc.cpp`）新增 `MergeMetaIntoParams`/`ExtractMetaFromParams`——序列化把 `meta` 合并进 `params._meta`，反序列化取出后从 params 移除 `_meta` 键；内存结构 `req.meta`/`notif.meta` 语义不变
- `WireCodec` Rev2026：`ValidateRequest` 改查 `params._meta`（除 `server/discover` 外缺失即 Invalid）；`StampOutgoingRequest` 写 `params._meta`
- `McpSessionHandler`：入站轻量校验视图把 `req.meta` 置于视图 params 内（与线上一致）；`SendRequest` 双 era 分支——modern era `req.meta` 写 `_meta` 信封，legacy era progressToken 写 `params._meta.progressToken`
- `include/mcp/JsonRpc.hpp` 两行过时注释同步修正（原描述"top-level _meta"）

## 2026-09-11-04 — progress 双向通道：服务端 SendProgress + 客户端 on_progress 回调

- `McpServer::SendProgress(token, progress, total?, message?)`（`include/mcp/server/McpServer.hpp` + `src/server/McpServer.cpp`）：向客户端发 `notifications/progress`，token 原样透传，`total`/`message` 可选
- `RequestOptions` 新增 `on_progress` 回调（`include/mcp/McpTypes.hpp`）；`McpClient` 经 `AttachProgressCallback` 注册回调并生成 progressToken（`options.meta.progressToken` 显式提供时优先，否则原子计数自 1 起自动生成），请求结束 RAII（`ScopedProgressCleanup`）清理
- `WireClientHandlers` 新增 `notifications/progress` 处理器：`ResetTimeoutByProgressToken` 顺延请求 deadline 后按 token 分发回调；回调在会话消息循环线程同步执行、须快速返回
- 缺陷修复：`RequestContext` 由存 `JsonRpcRequest` 指针改为**存值**——异步工具 handler 延迟执行时原请求对象可能已析构，存值使 `GetRequest()` 在异步场景安全

## 2026-09-11-04 — 客户端 SendRootsListChanged（版本门控）

- `McpClient::SendRootsListChanged()`：发送 `notifications/roots/list_changed`，协商版本 **>= 2025-06-18**（`kProtocolVersions` 序位比较）才允许，否则抛 `McpError(ProtocolViolation)`

## 2026-09-11-04 — Streamable HTTP 客户端 GET SSE 接收流

- `HttpClientTransportOptions` 新增 `enable_listen_stream`（**默认 true**）：发送 `notifications/initialized` 后自动在独立 `mcp-listen` 线程开 GET SSE 长流（WinHTTP/POSIX 两平台一致），服务端推送的通知经 SSE 分块解析后经 MessageChannel 并入会话引擎分发
- 405 视为服务器不支持（`ListenState::Unsupported`，静默放弃）；断线退避重连 1s 起倍增封顶 30s、最多 5 次（超限 `GivenUp`），重连携带 `Last-Event-ID`；单流读超时 600s
- `Close()` 顺序：先停 listen 流（句柄中断在途 GET 并 join 线程）再关 POST 通路，避免 Close 阻塞在 GET 读上

## 2026-09-11-04 — MCP-Protocol-Version 头自学习

- Streamable HTTP 客户端 initialize 请求**不再携带** `MCP-Protocol-Version` 头；从 initialize 响应 `result.protocolVersion` 学习（POST 响应体与 GET 流首帧均可学习），后续请求与 GET 流按学习值携带，无学习值兜底 `2026-07-28`（`ProtocolVersionHeaderFor`/`EffectiveProtocolVersion`/`NegotiatedVersionFromResponse`）
