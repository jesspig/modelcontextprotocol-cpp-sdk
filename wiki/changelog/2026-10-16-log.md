## 2026-10-16-01 补齐断言分支大括号消除 GCC 悬垂 else 告警（develop CI 由红转绿）

- **范围**：`tests/unit/HttpServerTests.cpp`（`327` 必改 + `1055` 同类）、`tests/unit/OAuthTests.cpp`（`1085` 同类）；`AGENTS.md` 5 处 googletest 迁移残留；`wiki/build.md` 补 GCC 独有告警事实。测试基线不变（17 目标 / 837 用例 / 3686 断言 token）。
- **失败事实**：CI run 38764091884（`develop`，`0ae76e7`）8 job 中仅 `build (ubuntu-24.04, debug, gcc)` 与 `build (ubuntu-24.04, release, gcc)` 红，均停在 Build 步，唯一诊断 `tests/unit/HttpServerTests.cpp:327:8: error: suggest explicit braces to avoid ambiguous 'else' [-Werror=dangling-else]`；其余 6 个 job（Windows-2022 双档、Linux-clang 双档、macOS-15 双档）全绿。
- **根因**：CI 对全部矩阵传 `-DMCP_WERROR=ON`（`ci.yml:76-94` → `CMakeLists.txt:56-66` 的 `mcp_enable_werror`）；googletest 断言经 `EXPECT_NE → EXPECT_PRED_FORMAT2 → GTEST_PRED_FORMAT2_ → GTEST_ASSERT_` 展开为 `GTEST_AMBIGUOUS_ELSE_BLOCKER_ if (...) ; else on_failure(...)`（`third_party/googletest/googletest/include/gtest/gtest_pred_impl.h:77-82`），宏体自带 `if/else`，作无括号单语句体时被 GCC `-Wall` 成员 `-Wdangling-else` 判为悬垂 else，`-Werror` 下成硬错误。
- **为什么只有 GCC 红**：GCC `-Wall` 启用 `-Wdangling-else`，clang 不启用；实测 clang 22.1.3 + 真实 gtest 头，即使显式加 `-Wdangling-else` 亦不报该形态，故 clang/clang-cl job 无此告警。
- **引入来源**：该行在自研框架时期即存在（`96afe15:tests/unit/HttpServerTests.cpp:327` 同写法），当时框架宏展开不含 `if/else` 故无害；`4469818 refactor(测试): 将测试框架由自研实现迁移至 googletest` 对该文件仅改 include 1 行，却使其变硬错误。同失败已在迁移合入 run 38754765350 出现，被 `master → develop` 合并（`0ae76e7`）原样带入当前 run。
- **修复**：`HttpServerTests.cpp:327` 与同类两处（`HttpServerTests.cpp:1055` 的 `if/else`、`OAuthTests.cpp:1085` 的 `for`）补 `{}`，零语义变化。
- **同类排查（GCC 实测）**：`if/for` 无括号 + 断言宏全仓共 3 处，GCC 实测只 `327` 报错（GCC 在同一 TU 内报全部诊断，故 `1055` 确实不报）；多行形态仅 `src/core/JsonParser.cpp:185` 命中，那是本地同名函数非 gtest 宏；`MCP_RUN_WITH_TIMEOUT`/`EXPECT_CALL_COUNT` 自定义宏展开无 `if/else` 且从未作无括号体使用。CI 覆盖面盲区一并补齐：GCC job 的 sccache 统计为 46/45 次编译请求（clang 同类 job 56 次），ninja 在首个失败处停下，约 10 个测试 TU（`mcp-message-filter-tests` 起）在 CI 中从未编译，本次扫描全部覆盖。
- **验证（实测）**：Ubuntu 24.04 + g++ 13.3.0（与 CI 同版本）以 CI Release 真实 flags（`-O3 -DNDEBUG -flto=auto -fno-fat-lto-objects -Werror`）+ `-DMCP_HAVE_OPENSSL` 编译 `tests/**/*.cpp` 全部 28 个 TU，`TOTAL=28 FAIL=1 → 0`（修复前仅 `327` 失败，修复后零诊断）；`src` + `tests` 共 70 文件 debug flags 扫描同样仅 `327`（另 2 处 `maybe-uninitialized` 位于 Alpine libstdc++ `variant:224`，Ubuntu 13.3 不重现，判为 Alpine 工具链假阳性；2 个 Windows-only 源文件在 Linux 本就不编）；本地 clang-cl `MCP_WERROR=ON` 全量构建 51 目标 `BUILD_EXIT=0` 零告警；`ctest --test-dir build/debug-werror` **837/837 全绿**（202.21s）。
