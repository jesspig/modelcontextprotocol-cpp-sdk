  **B 类行为收紧（源码兼容、线协议收紧）迁移**：
  - 旧行为：形如 `{"jsonrpc":"2.0","method":"x","id":1,"result":{}}`、`{"jsonrpc":"2.0","method":"x","id":null}`、`{"jsonrpc":"2.0","id":1.5,"result":{}}` 的畸形消息会被旧 `DeserializeMessage` 按 method/result 顺序静默归类或由 getter 抛通用 `DeserializeFailed`；字符串 `"1"` 与整数 `1` 在内部 key 中可能碰撞；订阅通知绕过 outgoing filter 与 span。
  - 新行为：上述畸形消息统一回 `McpError(McpErrorCode::InvalidRequest, ...)`；请求与成功响应 id 只接受 int64/string；内部 key 带 `i:`/`s:` 标签；订阅通知逐条走 `SendMessage`（filter/span/one-shot）。
  - 受影响怎么改：需要构造请求的调用方应确保 `id` 为整数或字符串且不与 `result`/`error` 同现；需要显式表达未知 id 的错误响应继续写 `"id":null`；依赖内部 key 文本格式的代码不存在（key 仅内部使用），若曾以日志中的裸 `1` 做匹配，改为按 `i:1`/`s:1` 区分；若希望订阅通知经过审计/限流，把对应 filter 挂到 `outgoing_filters` 即可，不再需要单独拦截发送路径。合法 legacy/modern 线协议与既有公开 API 均未删除、未改名。
