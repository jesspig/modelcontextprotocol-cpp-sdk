# 0.3.13 迁移与发布候选说明

> **状态**：0.3.13 **发布候选**，尚未打 tag。`include/mcp/McpVersion.hpp` 的 `mcp::kSdkVersion` 仍为 `"0.3.12"`，版本号、tag 与发布元数据由后续发布任务收口；本页只描述当前候选相对已发布 0.3.12 的公共头文件与行为差异，不宣称已发布。

0.3.13 的主线是把 OAuth、Tasks、Skills、会话、HTTP、存储、扩展与校验上的安全边界统一收紧。相对 0.3.12，公共头文件**没有删除任何声明、没有改旧签名、没有改旧默认值以外的字段语义**；变化集中在新增类型/字段/重载，以及 13 组 B 类行为收紧。本文把每一项的旧行为、新行为、受影响调用方与完整可编译迁移写法逐项列出；可编译片段统一放在 `docs/snippets/migration-0.3.13.cpp`，由 `mcp-docs-snippets` 真实语法检查。

## 兼容性分级

- **A 类（内部实现或源码兼容新增）**：不改变源码签名与既有默认行为。`DiscoverWithPolicy` 补 OIDC discovery 回退候选、`ext::AppsHostBridge`、`ext::FetchServerCard`、`ServerCardClientOptions`、`SkillReadParts` 三参数重载、`CurrentNegotiationSnapshot()`、`ITokenCache` 三个带默认实现的 DPoP 方法、`FileInputConfig` 可选字段、HTTP 回调上下文别名回迁、WebSocket 帧头解析器抽取，均属此类。A 类**无迁移项**，下文逐项明确写「无」。
- **B 类（源码兼容、行为收紧）**：旧代码仍能编译，但运行语义更严格，需按「旧行为 / 新行为 / 受影响怎么改」核对。本候选共 13 组，逐项见下表。
- **C 类（新增编译警告）**：新增的 `[[nodiscard]]` 只出现在**新增**符号上（协商快照、技能解析助手、卡片客户端助手、DPoP 校验、URL 安全策略内部助手等）；旧 API 没有被加警告属性。不需要为旧代码做 `(void)` 消除；新调用若不使用返回值，按各自说明写 `(void)`。
- **破坏性变更**：无。没有删除公共声明、没有修改旧签名、没有把旧默认值改成相反语义而无可迁移路径；`tests/compat/expected_breaks.txt` 保持上一版逐字口径，条目只减不增。

### OAuth 元数据与资源标识

- **旧行为**：广告 `authorization_response_iss_parameter_supported` 时授权响应缺 `iss` 放行；元数据缺 `code_challenge_methods_supported` 仍继续；PRM 不可达回退 RFC 8414 与 `server_url` 硬编码端点；`resource` 做去 fragment/尾斜杠归一化或 scheme+host 前缀比较；`OAuthMetadata::Discover(url)` 的第二参数默认 `true`；URL 形态 `client_id` 允许任意 `http(s)://`。
- **新行为**：三个默认值收紧；`resource` 逐字精确相等；`Discover(url)` 第二参数默认 `false` 并新增可选第三参数；CIMD `client_id` 仅 HTTPS 非根 path 且无 fragment/userinfo。
- **受影响调用方**：依赖旧 AS 元数据或缺 `iss` 响应的客户端；把 AS base 当 `resource` 的集成；用 `http://` CIMD URL 的部署。

### HTTP 绑定、边界与 AutoDetect

- **旧行为**：`HttpServerOptions::bind_host` 空值为 `INADDR_ANY`；重复/非法 `Content-Length` 被覆盖或宽容；SSE 各路径各自按 `\n\n` 分块；202 对请求也只记日志；`AutoDetect` 无运行时回退。

### DPoP、缓存与协商快照

### 存储损坏恢复与原子写

- **旧行为**：损坏后清空整库；末行残片只忽略不重写；游标失真仍被信任；`WriteAtomic` 非独占且不防链接。
- **新行为**：损坏先做字节一致备份再以合法前缀原子重建，失败保留原文件并抛 `InternalError`；残片原子重写；每次追加以日志为准校验游标；临时文件独占/no-follow/权限创建并刷父目录。旧单对象快照、JSONL 行与 `.meta.json` 仍可读。
- **受影响调用方**：依赖「损坏后空库」的调用方改为处理 `InternalError` 并检查 `.corrupt` 备份；手工追加 JSONL 而不更新游标的工具改走 `Append`；依赖覆盖符号链接目标的部署改为普通文件路径。**无需改公共 API 调用代码**。

### Server Card 与 FileInput

- **旧行为**：`/server-card` 返回固定 5 键、可选字段不写出；无 ETag，卡片处理器重复写 CORS；`enable_file_input=true` 隐式信任临时目录与当前目录，引用数/总字节无上限。

### 关闭与重连 generation

- **旧行为**：同一客户端工厂重复 `Connect()` 返回互不干扰的多个会话；旧 generation 回调继续投递。
