# 0.3.10 发布说明

> **状态**：0.3.10 发布版。`include/mcp/McpVersion.hpp` 的 `mcp::kSdkVersion` 为 `"0.3.10"`，本页的签名、字段与默认值已逐条对照 `include/mcp/` 的最终公共头文件核对。本版交付进程、会话与取消三组能力：公共进程 API（`Spawn`）、`RequestContext::SessionId()`、`McpServer::Elicit`/`ElicitUrl` 的会话参数、请求句柄与取消/错误分型；本版引入的破坏与限制全部列在下文「限制」节。

0.3.10 是 **patch** 版本。0.x 阶段不承诺跨版本源码兼容；本版不恢复 0.3.9 删除的字段，也不新增兼容 shim。0.3.9 的迁移项继续有效，升级前请先阅读 [0.3.9 迁移指南](0.3.9.md)。

## 新增 API

### 进程生命周期（公共进程 API）

新增 `SpawnOptions`、`SpawnedProcess` 与 `Spawn`：

```cpp
struct SpawnOptions {
    std::string command;
    std::vector<std::string> arguments;
    std::string working_directory;
    std::map<std::string, std::string> environment;
    bool inherit_environment = true;
    std::string stdout_path;
    std::string stderr_path;
    bool detached = false;
};

class SpawnedProcess {
public:
    virtual ~SpawnedProcess() = default;
    virtual int64_t Pid() const = 0;
    virtual bool IsRunning() const = 0;
    virtual bool Wait(int timeout_ms) = 0;
    virtual std::optional<int> ExitCode() const = 0;
    virtual bool Terminate(int grace_ms) = 0;
};

std::unique_ptr<SpawnedProcess> Spawn(const SpawnOptions& options);
```

- `environment` 在 `inherit_environment=true` 时覆盖或追加父环境；为 `false` 时只使用该 map。
- `stdout_path` / `stderr_path` 为空表示继承或使用管道默认；非空时创建或截断目标文件。
- `Wait` 返回 `true` 表示已退出，`false` 表示超时；退出码通过 `ExitCode()` 读取。
- `Terminate` 先优雅终止，宽限期后强杀；Windows 使用 Job Object 结束进程树，POSIX 使用进程组并回收子进程，避免僵尸。
- 参数不经 shell 拼接。
- stdio 传输**不调用**本节的公共 `Spawn`：`src/transport/StdioClientTransport.cpp` 经内部 `mcp::detail::CreateProcess`（`include/mcp/transport/detail/PlatformIO.hpp`）启动子进程。两条路径共用底层平台辅助 `src/process/detail/PosixProcessSupport.hpp` 与 `WindowsProcessSupport.hpp`，但公共 `mcp::Spawn` 在本版生产代码中没有调用者，仅 `tests/unit/ProcessTests.cpp` 与 `tests/unit/ProcessTestHelper.cpp` 使用。

### 会话上下文

新增 `RequestContext::SessionId()`：

```cpp
template <typename TParams>
class RequestContext {
public:
    std::string_view SessionId() const;
};
```

语义：

| 传输 | 返回值 |
| --- | --- |
| stateful Streamable HTTP | 当前请求对应的 `mcp-session-id`；同一会话稳定，不同会话不同 |
| stdio | 空字符串 |
| stateless HTTP | 空字符串 |

多会话按“每 session 一个 transport/server session”实现，HTTP 层按 `mcp-session-id` 路由；`RequestContext` 持有 `std::string` 拷贝，不引用会被并发改写的全局 session id。`McpServer::SessionId()` 从 0.3.9 起已存在，表示服务端实例 ID；它不冒充 MCP 会话 ID。

### Elicitation 的会话定位

`McpServer::Elicit` 与 `McpServer::ElicitUrl` 新增尾随的 `session_id` 参数（0.3.9 的这两个方法没有该参数）：

```cpp
std::future<ElicitResult> Elicit(const ElicitRequestParams& params,
    std::string_view session_id = {});
std::future<ElicitResult> ElicitUrl(const std::string& url,
    const std::string& message,
    std::chrono::seconds timeout = std::chrono::seconds(600),
    std::string_view session_id = {});
```

- 作用：服务端向客户端发起 elicitation 前，必须按目标会话解析客户端能力与协商协议版本——stateful Streamable HTTP 多会话下，`initialize` 上报的能力与协商版本只写入按 `mcp-session-id` 建立的会话表，全局成员只在会话 ID 为空（stdio/stateless）时写入，不传 `session_id` 就取不到目标会话的 elicitation 能力。
- `session_id` 为空时的回退顺序：显式传入的会话 > 已有全局能力时按全局 > 会话表只有一个非空会话时用该会话 > 其余情况回到全局。
- `Elicit` 没有超时参数，等待时限取 `ServerOptions::input_required_config->round_timeout`，未配置时为内部默认 600s；`ElicitUrl` 的 `timeout` 默认 `std::chrono::seconds(600)`。
- 协商版本为 modern（`>= "2026-07-28"`）时，两者都不直接外发 elicitation 请求，而是产出 `input_required` 交由 MRTR 续轮。

### 请求句柄、取消与错误模型

新增 `RequestHandle`、`CancelToken` 与 `IRequestCanceller`；分型结果 `RequestOutcome` 沿用 0.3.9 已有的定义：

```cpp
using RequestOutcome = std::variant<JsonValue, ErrorData>;

struct RequestHandle {
    RequestId id;
    std::future<RequestOutcome> future;
    RequestHandle(RequestHandle&&) noexcept = default;
    RequestHandle(const RequestHandle&) = delete;
    void Cancel(std::string_view reason = {});
};

struct RequestOptions {
    std::optional<JsonValue> meta;
    std::optional<int64_t> read_timeout_ms;
    std::optional<JsonValue> input_responses;
    std::optional<std::string> request_state;
    std::function<void(const ProgressNotificationParams&)> on_progress;
    std::chrono::milliseconds timeout{kDefaultRequestTimeout};
    bool cancel_on_timeout{true};
    CancelToken cancel_token;
};

RequestHandle SendRequest(
    std::string_view method,
    JsonValue params,
    const RequestOptions& options);

std::future<JsonValue> SendRequest(
    std::string_view method,
    JsonValue params,
    const RequestMeta& meta = {},
    std::chrono::milliseconds timeout = kDefaultRequestTimeout);

std::future<JsonValue> SendRequestRaw(
    std::string_view method,
    JsonValue params,
    const RequestMeta& meta = {},
    std::chrono::milliseconds timeout = kDefaultRequestTimeout);
```

- `RequestHandle` 同时提供请求 ID、结果 future 与取消入口，调用方不需要自己推断 ID；它只能移动，拷贝构造与拷贝赋值被删除。
- `CancelRequest(const RequestId&, std::string_view reason = {})` 保留，作为按 ID 取消的高级入口。
- `RequestOptions` 共 8 个字段：`meta`、`read_timeout_ms`、`input_responses`、`request_state`、`on_progress` 沿用 0.3.9；本版新增 `timeout`（默认 `kDefaultRequestTimeout`，即 60000ms）、`cancel_on_timeout`（默认 `true`）与 `cancel_token`。
- `cancel_on_timeout` 默认 `true`。stdio/legacy 发送 `notifications/cancelled`；modern 版本下若传输实现了 `IRequestCanceller`，走该接口中断这一请求的 SSE 流。`IRequestCanceller` 是独立接口，不修改 `ITransport` 虚表。
- `RequestHandle::future` 返回 `std::future<RequestOutcome>`，调用方显式区分 `JsonValue` 与 `ErrorData`；`SendRequestRaw` 保留 raw JSON 语义，错误以 `{"code","message"}`（可带 `data`）交付。
- 高层 `CallTool` / `ListTools` 继续抛 `McpError`，不再在同一入口混用错误 JSON 与异常。
- 0.3.9 的 `McpClient::SendRequest` 只有返回 `std::future<JsonValue>` 这一个重载；本版保留它（内部转发到 `SendRequestRaw`，`SendRequestRaw` 是本版新增），并新增返回 `RequestHandle` 的重载。
- 返回 `RequestHandle` 的重载**没有默认实参**，`method`、`params`、`options` 三个实参必须全部给出；两参数写法 `SendRequest(method, params)` 仍解析到 `std::future<JsonValue>` 重载，行为与 0.3.9 一致。

### 兼容 smoke（内部构建目标）

新增 `mcp-compat-smoke` 构建目标：

```bash
cmake --build --preset debug --target mcp-compat-smoke
```

它编译 `tests/compat/previous_public_api.cpp` 中的上一版公共 API 用法，并按 `tests/compat/expected_breaks.txt` 允许已知破坏（该 allowlist 当前记录的是 0.3.8 → 0.3.9 的破坏项，本版未新增条目）。基线翻译单元必须编译通过，已知破坏必须失败，非 allowlist 的编译失败会使目标失败；同时运行 `FileRef` 严格反序列化与 `ResourceLink` 必填 `name` 的运行时检查（由 `mcp-compat-runtime` 可执行文件承担，`mcp-compat-smoke` 负责构建并调用它）。该目标不注册进 ctest，不改变现有测试目标数量。

## 行为修复

- **取消语义**：超时与显式取消都会尽快结束等待；stdio/legacy 走 `notifications/cancelled`，modern HTTP 关闭对应请求流。调用方应按“最终一致”处理取消，不要假设取消一定先于响应到达。
- **错误模型**：请求结果与协议错误在 `RequestOutcome` 中分型；raw 入口保留 JSON 错误对象，高层入口继续抛 `McpError`，避免同一入口两种错误形态混用。
- **会话隔离**：stateful HTTP 按 `mcp-session-id` 建立独立会话上下文；任务 owner 绑定会话，跨会话不可枚举、不可读取或取消他人任务；stdio/stateless 的会话 ID 为空字符串。
- **进程生命周期**：`Spawn` 不经过 shell，Windows 使用 Job Object 结束进程树，POSIX 使用进程组与 `waitpid` 回收；`Terminate` 先优雅后强杀，`Wait` 有超时语义。
- **0.3.9 修复保留**：`ResourceLink` 字段校验、`FileRef` 严格 int64、URL elicitation 三态、MRTR 默认自动驱动、缓存授权上下文分区等行为不变。

## 限制

- **不恢复 0.3.9 删除的字段**：`ClientOptions::enable_apps_extension`、`ServerOptions::InputRequiredConfig::legacy_shim`、`ServerOptions::enable_dpop`、`ServerOptions::enable_interceptor_alias` 保持删除状态。
- **不提供旧 void URL handler 重载**：只保留 deprecated 的 `SetLegacyUrlElicitationHandler`，它固定 `accept`，不具备三态能力。
- **不提供兼容 shim**：0.x 不承诺跨版本源码兼容；0.3.10 仍可能有破坏，所有破坏项必须写入本页与 0.3.9 迁移页。
- **`FileRef` 严格校验**：分数、NaN、无穷大、越界值和非数字字段抛 `DeserializeFailed`，不会回退到 0 或截断。
- **`ResourceLink` 必填 `name`**：缺少或空 `name` 在序列化与反序列化时抛 `InvalidParams`。
- **modern 取消依赖 `IRequestCanceller`**：只有实现了该接口的传输才走请求级中断（内置 `StreamableHttpClientTransport` 满足）；未实现时 modern 与 legacy 一样回退 `notifications/cancelled`，本地等待仍会尽快以 `RequestCancelled`（显式取消）或 `RequestTimeout`（超时）结束，但对端在途的请求流不会被中断。
- **未声明的能力范围不变**：完整 sampling、Apps UI 渲染、jwt-bearer 授权等仍按 README 的“不支持声明”处理，本版不扩大承诺。

## 从 0.3.9 升级

1. 按 [0.3.9 迁移指南](0.3.9.md) 完成字段与签名替换。
2. 需要请求句柄与分型结果时改调 `SendRequest(method, params, options)`（三个实参都要给）；返回 `std::future<JsonValue>` 的旧重载保持不变，可以继续用，也可等价地改用本版新增的 `SendRequestRaw`。
3. 为进程启动配置 `SpawnOptions`，不要把命令拼成 shell 字符串。
4. 需要会话隔离的服务端代码通过 `RequestContext::SessionId()` 读取会话 ID，不要依赖全局变量。
5. 运行兼容 smoke 与全量测试：

```bash
cmake --preset debug
cmake --build --preset debug --target mcp-compat-smoke
cmake --build --preset debug
ctest --preset debug --output-on-failure
```
