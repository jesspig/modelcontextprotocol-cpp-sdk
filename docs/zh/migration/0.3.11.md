# 0.3.11 发布说明

> **状态**：0.3.11 发布版。`include/mcp/McpVersion.hpp` 的 `mcp::kSdkVersion` 为 `"0.3.11"`，本页的签名、默认值与限制均以该版本的公共头文件为准。

0.3.11 是 **patch** 版本，主线是把既有契约显式化并加固传输与协议边界：公共头文件补 `[[nodiscard]]`、编译期前提断言与调试期不变量；HTTP/SSE、协议引擎、任务存储、网络栈修掉一批并发与边界缺陷；同时首次启用兼容性分级与弃用登记（见 [弃用登记表](/zh/learn/compatibility)）。

## 兼容性分级

按兼容性宪法分三类，逐项归属见下文：

- **A 类（完全兼容）**：只改内部实现，公共签名与线协议行为不变。本版多数修复属此类。
- **B 类（源码兼容 + 行为收紧）**：签名不变，运行时或线协议更严格。本版包括重复关键请求头拒绝、请求头累计预算、事件回放上限、响应队列上限、listen 条目上限与过期淘汰、modern era 停发 `-32002`。
- **C 类（源码兼容 + 新增编译告警）**：新增 `[[nodiscard]]`、编译期 `static_assert` 前提断言与调试期不变量断言。

## 新增与变更

- **契约属性**：`JsonValue`、`JsonRpc`、`Transport`、`CancelToken`、`ProtocolVersion`、`ClientOptions`、`McpClient`、`OAuthClientProvider`、`TokenCache`、`SkillVerify`、`VersionNegotiation` 等公共头文件的返回值补 `[[nodiscard]]`。
- **编译期前提**：`ProtocolVersion.hpp` 断言版本表严格升序、modern 阈值自洽；`Limits.hpp` 断言 stdio 帧、SSE 事件、HTTP 体、DCR 与通道容量之间的大小关系。
- **调试期不变量**：`MessageChannel`、`SessionStore`、`EventStore`、`StreamableHttpServerTransport`、`McpSessionHandler`、`WireCodec` 在调试构建下对队列、容量与编码前提做断言。
- **可配置上限**：协议引擎响应队列容量可经 `SetResponseQueueCapacity()` 调整（默认 1024）；HTTP 服务端请求超时新增 `request_timeout`；SSE 回放上限新增 `max_sse_replay_bytes`。
- **鉴权**：OAuth 客户端按 RFC 9207 校验授权响应的签发方（`authorization_response_iss_parameter_supported`），对尚未提供 `iss` 的服务端保留兼容窗口。
- **事件存储**：`Append` 改为旁路游标文件实现 O(1) 追加。
- **构建**：新增 clang-tidy 检查基线配置、地址与线程消毒器开关；`-Werror` 不再传播给使用方。

## 行为修复

- **HTTP 服务端**：重复关键请求头直接拒绝；请求头读取改为累计预算（64 KiB / 100 个头）；慢速 SSE 客户端不再阻塞广播；事件回放加条数与字节上限且超限不截断帧分隔符；`Stop()` 不再交叉等待自身连接线程；请求超时可配置。
- **协议引擎**：请求表按会话隔离；响应队列设上限；取消通知不再结算本端出站请求；通知回调纳入统一异常守卫。
- **SSE 客户端**：支持 CRLF 分帧；长流不再被响应体上限截断；重连预算在收流成功后重置。
- **会话与任务**：`listen` 条目按客户端 id 幂等并加会话上限与过期淘汰；任务收尾按存储真实状态发送通知；过期清扫跳过非终态任务；输入等待中的任务不接受结果直接完成。
- **网络栈**：派生进程不再继承父进程套接字；TLS 关闭不在持锁期间等待；TLS 对 IP 字面量使用 iPAddress 校验；socket 关闭与读写不再复用文件描述符；HTTP 客户端关闭不再清空共享读缓冲；`accept` 的连接套接字设为非阻塞；TLS 共享上下文显式加载 `SSL_CERT_FILE`。
- **其他**：`extensions/list` 读寄存器时持共享锁；`tools/list` 缓存提示按会话现算；`capabilities` 非对象抛错、Schema 数值等值语义与 elicit 兜底告警。

## 弃用与限制

- **弃用**：`McpErrorCode::ResourceNotFound`（`since 0.3.11, removed in 0.4.0`）改用 `InvalidParams`；modern era 起不再发送 `-32002`。完整登记与替代写法见 [弃用登记表](/zh/learn/compatibility)。
- **限制**：响应队列默认 1024；请求头 64 KiB / 100 个；SSE 事件与回放上限受 `kMaxMessageSize` 关系约束（回放默认等于单事件上限）；`listen` 条目有会话上限与过期时间；`Elicit` 等待受 `input_required_config` 的轮次与时限约束。

## 从 0.3.10 升级

- **A 类无需改动**：升级后重新编译即可。
- **C 类**：`[[nodiscard]]` 返回值若刻意忽略，写 `(void)call;`；`static_assert` 失败说明违反了编译期容量前提，按报错调整配置常量，不要删除断言。
- **B 类**：按下表逐项核对「旧行为 / 新行为 / 受影响时怎么改」。

| 项 | 旧行为 | 新行为 | 受影响时怎么改 |
|---|---|---|---|
| 重复关键请求头 | 接受，可能后值覆盖先值 | 直接拒绝 | 发送端去重，只保留一个 `Host`、`Content-Length` 等关键头 |
| 请求头读取 | 单次读取、无累计上限 | 累计预算 64 KiB / 100 个头 | 精简头部或拆小请求 |
| 事件回放 | 无条数与字节上限 | 受 `max_sse_replay_bytes` 与条数上限约束 | 减少 `Last-Event-ID` 之后的回放量，或调大上限 |
| 响应队列 | 无界 | 默认 1024，超限拒绝入队 | 用 `SetResponseQueueCapacity()` 调整，或加快出站消费 |
| `listen` 条目 | 无上限、重复注册不幂等 | 按客户端 id 幂等，有会话上限与过期淘汰 | 复用客户端 id，或调大上限 |
| modern era `-32002` | 可能收到或发送 | 不再发送，统一 `-32602 InvalidParams` | 收端按 `InvalidParams` 处理；发端改用 `InvalidParams` |

## 验证与发布收口

- **测试基线**：18 个测试目标 / Windows 本机 `ctest` 注册 1019 例 / 静态用例 1030 / 静态断言 4873（`MCP_WITH_OPENSSL=AUTO` 未探到 OpenSSL 档）。
- **CI**：develop `53db38f` 的 CI 全部 14 个作业通过，覆盖 ASan+UBSan、TSan、install consumer、compat smoke、examples 构建与 OpenSSL 3 / OpenSSL 4 两个大版本矩阵；同提交的 Conformance 与 Docs Validate 通过。
- **平台修复**：macOS 慢速 SSE 用例与 Windows debug TLS 用例的问题在本版定位并修复（`accept` 连接套接字非阻塞、TLS 共享上下文显式加载 `SSL_CERT_FILE`），由上述 CI 复核。
- **未验证**：本页不覆盖 0.4.0 的移除项；`ResourceNotFound` 的移除在 0.4.0 发生，届时需同步 [弃用登记表](/zh/learn/compatibility)。
