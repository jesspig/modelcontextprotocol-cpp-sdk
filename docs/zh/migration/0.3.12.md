# 0.3.12 发布说明

> **状态**：0.3.12 发布版。`include/mcp/McpVersion.hpp` 的 `mcp::kSdkVersion` 为 `"0.3.12"`，本页的新增接口、默认值与限制均以该版本的公共头文件为准。

0.3.12 是 **patch** 版本，主线是补齐高层客户端读取能力、加固 OAuth 发现回退与客户端可靠性，并给出 legacy 错误的解析帮手。本版**全部为源码兼容的新增与修复**，没有引入破坏性变更，也没有新增编译告警；弃用登记表（见 [弃用登记表](/zh/learn/compatibility)）与上一版逐字一致。

## 兼容性分级

按兼容性宪法分三类，本版逐项归属如下：

- **A 类（完全兼容）**：只改内部实现或修缺陷，公共签名与线协议行为不变。OAuth 回退开关默认 `true` 保持旧行为、订阅关闭取消、Pin 模式赋值修复均属此类。
- **新增 API（源码兼容）**：`ReadSkill`、`ReadSkillDirectory`、`ParseUrlElicitationRequired` 为新增符号，既有调用点不受影响。
- 本版**无 B 类（行为收紧）与 C 类（新增编译告警）**变更。

## 新增与变更

- **Skills 高层读取**：`McpClient` 新增 `ReadSkill(uri, options?)` 与 `ReadSkillDirectory(uri, options?)`，一次调用完成 manifest 拉取、逐文件下载与 size/digest/frontmatter 校验，返回结构化结果（`SkillReadResult` / `SkillDirectoryReadResult`）。实现复用 `SkillVerify` 原语与既有分页/缓存策略，不改变 `ListSkills` / `GetSkill` / `ReadDirectory` 行为。校验失败写入 `diagnostics[].uri/reason`（`size_mismatch`、`digest_mismatch`、`frontmatter_mismatch`），不抛异常；网络与协议错误仍沿既有 `McpError` 透传。
- **OAuth 发现回退开关**：`OAuthClientOptions` 新增 `allow_legacy_metadata_fallback`（默认 `true`，保持既有回退行为）；`OAuthMetadata::Discover` 增加默认参数 `allow_legacy_fallback = true`。显式关闭后，PRM 不可达或 AS 元数据为空时不再回退到资源服务器 origin 的 RFC 8414 文档，返回空。issuer 绑定、`iss` 校验与刷新语义不变。安全敏感部署可显式关闭该回退。
- **legacy URL elicitation 解析**：新增 `ParseUrlElicitationRequired(const McpError&)`，解析 `-32042` 错误的 `data.elicitations`，返回含 `mode` / `elicitation_id` / `url` / `message` 的可选结果；错误码不符或字段缺失返回空、不抛异常。仅用于 legacy `2025-11-25` 协商（现代版本已改用 MRTR `InputRequiredResult`），不自动重试原请求。注意 wire 字段 `elicitationId` 对应 C++ 成员 `elicitation_id`（仓库 snake_case 约定）。

## 行为修复

- **订阅关闭取消**：新增内部 `ClearPendingSubscriptionAck()`，在 `Close()` 与传输关闭回调中唤醒等待线程；传输独立关闭后 `SubscribeAsync` 在一个轮询周期内确定性返回，不再等到 5 秒超时抛 `InternalError`。成功路径与错误码不变，未新增线程 join。
- **Pin 模式协商**：删除 `ConnectMode::Pin` 分支中把客户端实现误写入 `discover.server_info` 的赋值；`DiscoverResult.server_info` 保持默认空，`GetServerInfo()` 行为不变。

## 弃用与限制

- **弃用**：沿用上一版登记，`ResourceNotFound`（`since 0.3.11, removed in 0.4.0`）仍以 `InvalidParams` 替代；本版无新增弃用项。
- **限制**：Skills 单技能总字节仍受现有上限约束；`ReadSkillDirectory` 分页不超过 64 页，超出抛 `ProtocolViolation`。

## 从 0.3.11 升级

- **无需改动**：本版全部为源码兼容新增与修复，直接重新编译即可；`Discover` 的新参数有默认值，既有单参调用保持不变。
- **可选启用**：需要完整契约校验的调用方改用 `ReadSkill` / `ReadSkillDirectory`；需要收紧发现回退的部署将 `allow_legacy_metadata_fallback` 显式设为 `false`。
- **无 B/C 类迁移项**：没有需要按「旧行为 / 新行为」对照修改的行为收紧，也没有需要 `(void)` 消除的新增告警。

## 预研与跟踪（不影响运行时）

- `io.modelcontextprotocol/files` 扩展目前为草案（2026-11-10 公布，依赖 `2026-07-28+`，官方无参考实现），本版只跟踪不实现；`enable_file_input` 只是工具参数内联引用能力，不等于该扩展。
- 下一版 spec `2027-03-30`（SEP-3398，2026-11-11 公告，尚未发布）的升级入口与 conformance 新场景已登记在项目内部知识库的协议跟踪清单中，本版不改动相关代码与基线。

- **测试基线**：18 个测试目标 / Windows 本机 `ctest` 注册 1037 例 / 静态用例 1048 / 静态断言 4961（`MCP_WITH_OPENSSL=AUTO` 未探到 OpenSSL 档）。
- **全量验证**：`cmake --preset debug`、`cmake --build --preset debug`、`ctest --preset debug --output-on-failure` 全部退出码 0，1037/1037 通过。
- **提交规范**：本版相对 0.3.11 的提交全部符合 `type(scope): 描述` 约定，非合并提交均带逐条正文。
- **未验证**：conformance 测试数沿用上一版口径（124），本版未重新统计；macOS 与 OpenSSL 平台矩阵以 CI 结果为准。
