# 0.3.9 迁移指南

本页覆盖 **0.3.8 → 0.3.9** 的公共头文件破坏性变更。0.3.9 处于 0.x 开发阶段，项目不承诺跨版本源码兼容；0.3.10 不会恢复这里删除的字段，也不提供兼容 shim。升级时请逐项对照旧写法与新写法。

## 变更总览

| 项目 | 变更类型 | 迁移动作 |
| --- | --- | --- |
| `ResourceLink` | 新增必填字段与可选字段 | 设置非空 `name`；按需补 `description`、`mime_type`、`size`、`icons` |
| `ClientOptions::enable_apps_extension` | 删除字段 | 删除赋值；服务端开关保留在 `ServerOptions::enable_apps_extension` |
| `ServerOptions::InputRequiredConfig::legacy_shim` | 删除字段 | 删除赋值；MRTR 默认自动驱动，`input_required_config = std::nullopt` 关闭 |
| `ServerOptions::enable_dpop` | 删除字段 | 改用 `StreamableHttpServerOptions::BearerAuthConfig::enable_dpop` |
| `ServerOptions::enable_interceptor_alias` | 删除字段 | 改用 `incoming_filters` / `outgoing_filters` |
| `UrlElicitationHandler` | 函数签名变更 | 返回 `ElicitResult`；旧 void 回调改用 `SetLegacyUrlElicitationHandler` |
| `McpServer::GetCapabilities()` | 返回类型变更 | 按值接收 `ServerCapabilities`，不要保存内部引用 |
| `FileRef::offset` / `FileRef::length` | 反序列化语义收紧 | 只接受 int64 范围内的整数值；非法值抛 `DeserializeFailed` |
| `CompleteRequestParams::context_arguments` | 新增字段 | 直接赋值 `std::map<std::string, std::string>` |
| `TaskState::owner` / `IMcpTaskStore` | 新增字段与虚函数 | 自定义任务存储按需实现 owner、TTL、过期回收 |
| `ClientOptions` handler 字段 | 新增字段 | 用成员赋值配置；新增 `DeriveClientCapabilities` |
| `OAuthClientOptions::allowed_authorization_server_origins` | 新增字段 | 配置跨源授权服务器白名单 |
| `StreamableHttpServerOptions::listen_hold_open` | 0.3.8 已存在，0.3.9 未变更 | 无需迁移 |
| 接口新增虚函数 | 源码兼容的增量 | 默认实现已提供，按需 override |

## 1. `ResourceLink` 新增必填 `name`

0.3.9 在 `ResourceLink` 中新增非可选 `name`，并新增 `description`、`mime_type`、`size`、`icons`：

```cpp
struct ResourceLink {
    std::string type = "resource_link";
    std::string uri;
    std::string name;
    std::optional<std::string> title = std::nullopt;
    std::optional<std::string> description = std::nullopt;
    std::optional<std::string> mime_type = std::nullopt;
    std::optional<int64_t> size = std::nullopt;
    std::vector<Icon> icons;
    std::optional<Annotations> annotations = std::nullopt;
    std::optional<JsonValue> meta = std::nullopt;
};
```

### 旧写法

```cpp
std::optional<std::string> title = "季度报告";
ResourceLink link{"resource_link", "file:///reports/q3.pdf", title,
                  std::nullopt, std::nullopt};
```

### 新写法

```cpp
ResourceLink link;
link.uri = "file:///reports/q3.pdf";
link.name = "季度报告";
link.title = "季度报告";
link.description = "第三季度财务报告";
link.mime_type = "application/pdf";
link.size = 1024;
link.icons.push_back(Icon{"https://example.com/pdf.png"});
```

### 影响

- 旧式聚合初始化会把 `title` 放进 `name`，或直接因类型不匹配而编译失败；请改用成员赋值。
- `SerializeResourceLink` 在 `name` 或 `uri` 为空时抛 `McpError(McpErrorCode::InvalidParams)`；`size` 为负同样抛 `InvalidParams`。0.3.8 代码只设置 `uri` 时，升级后会在序列化阶段报错。
- `DeserializeResourceLink` 要求对端提供非空 `name` 与非空 `uri`；缺少 `name` 的旧 wire 数据不再被接受。
- `icons` 使用 `Icon{src, mime_type, sizes, theme}`；只有非空集合才会写入 wire。

## 2. `ClientOptions::enable_apps_extension` 已删除

### 旧写法

```cpp
ClientOptions options;
options.enable_apps_extension = true;
```

### 新写法

```cpp
ClientOptions options;
// 客户端没有 apps extension 开关；服务端需要声明时使用 ServerOptions。
ServerOptions server_options;
server_options.enable_apps_extension = true;
```

### 影响

- `ClientOptions::enable_apps_extension` 在 0.3.8 中没有读取点，删除不会改变客户端行为；旧代码只需删除该行。
- `ServerOptions::enable_apps_extension` 仍然存在，继续控制服务端 `io.modelcontextprotocol/ui` 扩展声明与 `ui://` 资源读取门控。

## 3. `ServerOptions` 三个无效开关已删除

这三个字段在 0.3.8 中都没有实际读取点，删除属于源码清理；升级时删除旧赋值即可。

### 3.1 `InputRequiredConfig::legacy_shim`

旧写法：

```cpp
ServerOptions options;
options.input_required_config.emplace();
options.input_required_config->legacy_shim = false;
```

新写法：

```cpp
ServerOptions options;
options.input_required_config.emplace();
options.input_required_config->max_rounds = 10;
options.input_required_config->round_timeout = std::chrono::seconds(600);

// 关闭自动 MRTR 驱动：
options.input_required_config = std::nullopt;
```

影响：0.3.9 的 MRTR 默认自动驱动，不再有 legacy shim 开关；需要保留未履行的 `input_required` 结果时，显式把 `input_required_config` 置为 `std::nullopt`。

### 3.2 `ServerOptions::enable_dpop`

旧写法：

```cpp
ServerOptions options;
options.enable_dpop = true;
```

新写法：

```cpp
StreamableHttpServerOptions http_options;
http_options.bearer_auth.emplace();
http_options.bearer_auth->enable_dpop = true;
```

影响：服务端 DPoP 开关只在传输配置上生效，且必须先配置 `bearer_auth`；DPoP 验签需要 OpenSSL。旧的 `ServerOptions::enable_dpop` 没有读取点。

### 3.3 `ServerOptions::enable_interceptor_alias`

旧写法：

```cpp
ServerOptions options;
options.enable_interceptor_alias = true;
```

新写法：

```cpp
ServerOptions options;
options.incoming_filters = std::make_shared<FilterPipeline>();
options.outgoing_filters = std::make_shared<FilterPipeline>();
options.incoming_filters->AddInterceptor(
    std::make_shared<MyFilter>());
```

影响：`Interceptor` 仍是 `MessageFilter` 的类型别名；过滤器通过 `incoming_filters` / `outgoing_filters` 显式接入。旧的 `enable_interceptor_alias` 没有读取点。

## 4. `UrlElicitationHandler` 改为返回 `ElicitResult`

### 旧写法

```cpp
client.SetUrlElicitationHandler([](const ElicitRequestParams&) {
    // 旧签名返回 void，SDK 固定按 accept 处理
});
```

`ClientOptions::url_elicitation_handler` 的旧赋值同样返回 void。

### 新写法

```cpp
client.SetUrlElicitationHandler([](const ElicitRequestParams& params) {
    ElicitResult result;
    result.action = "accept";
    result.content = JsonValue::Object{{"confirmed", true}};
    return result;
});
```

也可以把 handler 放进 `ClientOptions`：

```cpp
ClientOptions options;
options.url_elicitation_handler = [](const ElicitRequestParams&) {
    ElicitResult result;
    result.action = "decline";
    return result;
};
```

### 影响

- handler 的 `action` 必须是 `accept`、`decline` 或 `cancel`；其他值抛 `McpError(McpErrorCode::HandlerError)`。
- 未配置 handler 时默认为 `decline`，不再默认 `accept`。
- 确实需要旧 void 行为时，使用 deprecated 的 `SetLegacyUrlElicitationHandler`；它把 action 固定为 `accept`，不提供新的三态能力。0.3.10 不会新增旧签名重载。
- legacy 时代仍会在响应后发送 `notifications/elicitation/complete`；modern 时代由 MRTR 的 `inputResponses` 完成往返。

## 5. `McpServer::GetCapabilities()` 改为按值返回

### 旧写法

```cpp
const ServerCapabilities& caps = server->GetCapabilities();
auto& mutable_caps = server->GetCapabilities(); // 0.3.9 编译失败
```

### 新写法

```cpp
ServerCapabilities caps = server->GetCapabilities();
const auto snapshot = server->GetCapabilities();
```

### 影响

- 返回类型由 `const ServerCapabilities&` 改为 `ServerCapabilities`。`const&` 绑定仍可能因生命周期延长而编译，但它绑定的是临时副本，不再引用 `McpServer` 内部状态。
- 需要引用或指针的旧代码会编译失败；请改为持有副本。
- 按值返回消除了调用方在锁外访问内部 `capabilities_` 的数据竞争风险；能力快照的拷贝成本远小于一次协议往返。

## 6. `FileRef` 的 `offset` / `length` 改为严格 int64

### 旧写法

```cpp
// 0.3.8：非数字被静默忽略，double 被截断。
FileRef ref = DeserializeFileRef(json);
```

### 新写法

```cpp
JsonValue json(JsonValue::object_tag);
json["uri"] = "file:///data.bin";
json["offset"] = int64_t{1024};
json["length"] = int64_t{4096};
FileRef ref = DeserializeFileRef(json);
```

### 影响

- `offset` / `length` 必须是 JSON 整数，或值为整数的 JSON double（例如 `1024.0`）；分数、NaN、无穷大、超出 int64 范围的值，以及字符串/布尔/null 都会抛 `McpError(McpErrorCode::DeserializeFailed)`。
- 0.3.8 对非数字字段静默保留默认值 0，对 double 直接截断；依赖这些宽松行为的下游需要先清洗 JSON 再调用。
- 序列化行为不变：`offset` / `length` 为 0 时不写入 wire，非 0 时按 `int64_t` 写出。

## 7. 补充项

### 7.1 `CompleteRequestParams::context_arguments`

0.3.9 新增 `context_arguments`，序列化时写入 `context.arguments`，仅在非空时出现：

```cpp
CompleteRequestParams params;
params.ref = JsonValue::Object{{"type", "ref/prompt"}, {"name", "weather"}};
params.argument_name = "city";
params.argument_value = "Shanghai";
params.context_arguments = {{"locale", "zh-CN"}, {"unit", "metric"}};
```

影响：旧的四字段聚合初始化（`{ref, name, value, meta}`）会把 `meta` 传给 `context_arguments` 而编译失败；请改用成员赋值。反序列化会校验 `context.arguments` 必须是对象且值为字符串。

### 7.2 `TaskState::owner` 与 `IMcpTaskStore` 新虚函数

`TaskState` 在 `task_id` 之后新增 `owner`，旧式聚合初始化会编译失败：

```cpp
TaskState state;
state.task_id = "task-1";
state.owner = server.SessionId();
state.status = TaskStatus::Pending;
```

`IMcpTaskStore` 新增以下虚函数，均带默认实现，已有自定义存储可以继续编译：

- `CreateTask(task_id, owner, ttl_ms)`：默认转调 `CreateTask(task_id)`，再调用 `SetTaskOwner` / `SetTaskTtl`。
- `FailTask`、`RemoveTask`、`GetExpiredTaskIds`、`SetTaskOwner`、`SetTaskTtl`。

影响：服务端用 `owner` 做会话隔离，空 owner 视为旧数据并保持可访问；希望启用 TTL 清理和会话隔离的自定义存储应 override 这些函数。`FileTaskStore` 已实现全部新虚函数。

### 7.3 `ClientOptions` handler 字段与新选项

0.3.9 把 handler 从 `McpClient` 的 setter 扩展到 `ClientOptions`，并新增若干选项：

```cpp
ClientOptions options;
options.elicitation_handler = [](const ElicitRequestParams&) {
    ElicitResult result;
    result.action = "accept";
    return result;
};
options.url_elicitation_handler = options.elicitation_handler;
options.sampling_handler = [](const CreateMessageRequestParams&) {
    return CreateMessageResult{};
};
options.roots_handler = [](const ListRootsRequestParams&) {
    return ListRootsResult{};
};
options.enable_etag_cache = true;
options.cache_auth_context = [] { return std::string("tenant-a"); };
options.on_transport_close = [] {};
options.on_transport_error = [](std::string_view message) {};
```

影响：新增字段插在 `capabilities` 与 `connect_mode` 之间，旧的 `ClientOptions{client_info, capabilities, connect_mode}` 聚合初始化会编译失败；请改用成员赋值。`DeriveClientCapabilities` 会根据 handler 自动补声明 elicitation、sampling、roots 能力，只有显式 `capabilities` 未覆盖的部分才会被补上。

### 7.4 `OAuthClientOptions` 新字段与 OAuth 加固

新增字段：

```cpp
OAuthClientOptions oauth;
oauth.allowed_authorization_server_origins = {"https://auth.example.com"};
```

影响：

- 该字段插在 `client_assertion_clock_seconds` 与回调字段之间；完整聚合初始化的代码需要调整位置，建议统一改用成员赋值。
- 授权服务器端点默认强制 https（loopback 例外）；跨源授权服务器必须与 `server_url` 同源或列入 `allowed_authorization_server_origins`。
- `OAuthClientProvider::IsSecureEndpoint` / `IsSameOrigin` 可用于复用同一判定。
- issuer 锚定通过 `ITokenCache::StoreBoundIssuer` / `GetBoundIssuer` 持久化；自定义 token cache 不 override 时仍可编译，但不会跨实例保留锚点。

### 7.5 `StreamableHttpServerOptions::listen_hold_open`

经 0.3.8 与 0.3.9 头文件核对，`listen_hold_open` 在 0.3.8 已存在，0.3.9 未改动，默认值仍为 `false`。它控制 `subscriptions/listen` 的 HTTP 响应是否持开，不是 0.3.9 的迁移项；无需修改现有配置。

### 7.6 其他接口新增虚函数

这些新增函数都提供默认实现，已有派生类无需修改即可编译；需要新行为时再 override。

- `ITransport::RequiresRequestScopedNotifications()`：默认 `false`；`StreamableHttpServerTransport` 返回 `true`。自定义传输若需要按请求隔离通知流，应 override。
- `ITokenCache::StoreBoundIssuer` / `GetBoundIssuer`：默认 no-op / `std::nullopt`；`InMemoryTokenCache` 与 `FileTokenCache` 已实现。
- `WireCodec::ValidateRequest` / `ValidateNotification` 的 `WireMessageView` 重载：默认转发到 `JsonValue` 重载；新增 `MakeWireRequestView` / `MakeWireNotificationView`。
- `IMcpTaskStore` 的 owner/TTL/过期相关虚函数见 7.2。

## 8. 其他 0.3.9 公共头文件变化

以下变化以增量为主，通常不需要迁移，但会出现在公共头文件中：

| 变化 | 说明 |
| --- | --- |
| `McpClient::SendRequest` / `SendNotification` / `CancelRequest` / `SetLoggingLevel` | 新增通用请求与控制入口；`SetLoggingLevel` 仅在 legacy 会话可用 |
| `McpServer::IsRunning()` / `SessionId()` | 新增运行状态与服务端会话标识 |
| `McpSessionHandler::SendRequest(..., OutcomeCallback)` | 新增带结果/错误分型回调的重载 |
| `McpSessionHandler::SetServerInfo` | 允许会话层注入 `serverInfo` |
| `IncomingRequestMeta` 中的 `RequestOutcome` / `OutcomeCallback` | 新增结果与 `ErrorData` 的分型类型 |
| `PendingRequest` 新增 `outcome_callback`、`method`、`request_id` | 旧式聚合初始化需要改为成员赋值 |
| `RequestContext` 构造函数新增默认参数 | 源码兼容；modern 下 `Log` 可按请求级 `logLevel` 门控 |
| `detail::WriteAtomicSecure` / `detail::WriteWholeMessage` | 内部工具新增；`FileTaskStore` / `FileTokenCache` 使用安全写 |
