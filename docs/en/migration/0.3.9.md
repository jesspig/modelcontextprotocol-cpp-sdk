# 0.3.9 Migration Guide

This page covers the public-header breaking changes from **0.3.8 to 0.3.9**. 0.3.9 is a 0.x development release, so cross-version source compatibility is not promised. 0.3.10 will not restore the fields removed here and will not add compatibility shims. Replace each old form with the new form below.

## Change overview

| Item | Change type | Migration action |
| --- | --- | --- |
| `ResourceLink` | New required and optional fields | Set a non-empty `name`; add `description`, `mime_type`, `size`, `icons` as needed |
| `ClientOptions::enable_apps_extension` | Field removed | Delete the assignment; the server switch remains `ServerOptions::enable_apps_extension` |
| `ServerOptions::InputRequiredConfig::legacy_shim` | Field removed | Delete the assignment; MRTR is auto-driven by default, disable with `input_required_config = std::nullopt` |
| `ServerOptions::enable_dpop` | Field removed | Use `StreamableHttpServerOptions::BearerAuthConfig::enable_dpop` |
| `ServerOptions::enable_interceptor_alias` | Field removed | Use `incoming_filters` / `outgoing_filters` |
| `UrlElicitationHandler` | Signature changed | Return `ElicitResult`; for the old void callback use `SetLegacyUrlElicitationHandler` |
| `McpServer::GetCapabilities()` | Return type changed | Take a `ServerCapabilities` value; do not keep an internal reference |
| `FileRef::offset` / `FileRef::length` | Deserialization tightened | Accept only integral values in int64 range; invalid values throw `DeserializeFailed` |
| `CompleteRequestParams::context_arguments` | Field added | Assign a `std::map<std::string, std::string>` directly |
| `TaskState::owner` / `IMcpTaskStore` | Field and virtuals added | Implement owner, TTL, and expiry in custom task stores as needed |
| `ClientOptions` handler fields | Fields added | Configure with member assignment; `DeriveClientCapabilities` is new |
| `OAuthClientOptions::allowed_authorization_server_origins` | Field added | Configure the cross-origin authorization-server allowlist |
| `StreamableHttpServerOptions::listen_hold_open` | Already present in 0.3.8, unchanged in 0.3.9 | No migration needed |
| New interface virtuals | Source-compatible additions | Default implementations exist; override only if needed |

## 1. `ResourceLink` now requires `name`

0.3.9 adds a non-optional `name` plus `description`, `mime_type`, `size`, and `icons`:

```cpp
struct ResourceLink {
    std::string type = "resource_link";
    std::string uri;
    std::string name;
    std::optional<std::string> title = std::nullopt;
    std::optional<std::string> description = std::nullopt;
    std::optional<std::string> mime_type = std::nullopt;
    std::optional<int64_t> size = std::nullopt;
    std::vector<Icon> icons;
    std::optional<Annotations> annotations = std::nullopt;
    std::optional<JsonValue> meta = std::nullopt;
};
```

### Old form

```cpp
std::optional<std::string> title = "Quarterly report";
ResourceLink link{"resource_link", "file:///reports/q3.pdf", title,
                  std::nullopt, std::nullopt};
```

### New form

```cpp
ResourceLink link;
link.uri = "file:///reports/q3.pdf";
link.name = "Quarterly report";
link.title = "Quarterly report";
link.description = "Q3 financial report";
link.mime_type = "application/pdf";
link.size = 1024;
link.icons.push_back(Icon{"https://example.com/pdf.png"});
```

### Impact

- Old aggregate initialization either places `title` into `name` or fails to compile on the type mismatch; use member assignment.
- `SerializeResourceLink` throws `McpError(McpErrorCode::InvalidParams)` when `name` or `uri` is empty, and when `size` is negative. Code that only set `uri` in 0.3.8 will now fail during serialization.
- `DeserializeResourceLink` requires a non-empty `name` and `uri`; old wire data without `name` is rejected.
- `icons` uses `Icon{src, mime_type, sizes, theme}`; only a non-empty collection is written to the wire.

## 2. `ClientOptions::enable_apps_extension` removed

### Old form

```cpp
ClientOptions options;
options.enable_apps_extension = true;
```

### New form

```cpp
ClientOptions options;
// The client has no apps-extension switch; use ServerOptions when the server
// needs to declare it.
ServerOptions server_options;
server_options.enable_apps_extension = true;
```

### Impact

- `ClientOptions::enable_apps_extension` had no read point in 0.3.8, so removing it does not change client behavior; delete the line.
- `ServerOptions::enable_apps_extension` remains and still gates the server's `io.modelcontextprotocol/ui` extension declaration and `ui://` resource access.

## 3. Three dead `ServerOptions` switches removed

All three fields had no read point in 0.3.8. Removing them is a source cleanup; delete the old assignments.

### 3.1 `InputRequiredConfig::legacy_shim`

Old form:

```cpp
ServerOptions options;
options.input_required_config.emplace();
options.input_required_config->legacy_shim = false;
```

New form:

```cpp
ServerOptions options;
options.input_required_config.emplace();
options.input_required_config->max_rounds = 10;
options.input_required_config->round_timeout = std::chrono::seconds(600);

// Disable automatic MRTR driving:
options.input_required_config = std::nullopt;
```

Impact: MRTR is auto-driven by default in 0.3.9 and the legacy-shim switch no longer exists. Set `input_required_config` to `std::nullopt` when you want unfulfilled `input_required` results returned to the caller.

### 3.2 `ServerOptions::enable_dpop`

Old form:

```cpp
ServerOptions options;
options.enable_dpop = true;
```

New form:

```cpp
StreamableHttpServerOptions http_options;
http_options.bearer_auth.emplace();
http_options.bearer_auth->enable_dpop = true;
```

Impact: the server-side DPoP switch lives on the transport configuration and requires `bearer_auth`; DPoP proof verification requires OpenSSL. The old `ServerOptions::enable_dpop` had no read point.

### 3.3 `ServerOptions::enable_interceptor_alias`

Old form:

```cpp
ServerOptions options;
options.enable_interceptor_alias = true;
```

New form:

```cpp
ServerOptions options;
options.incoming_filters = std::make_shared<FilterPipeline>();
options.outgoing_filters = std::make_shared<FilterPipeline>();
options.incoming_filters->AddInterceptor(
    std::make_shared<MyFilter>());
```

Impact: `Interceptor` is still an alias of `MessageFilter`; filters are attached explicitly through `incoming_filters` / `outgoing_filters`. The old `enable_interceptor_alias` had no read point.

## 4. `UrlElicitationHandler` now returns `ElicitResult`

### Old form

```cpp
client.SetUrlElicitationHandler([](const ElicitRequestParams&) {
    // The old signature returned void; the SDK forced accept.
});
```

The old `ClientOptions::url_elicitation_handler` assignment also returned void.

### New form

```cpp
client.SetUrlElicitationHandler([](const ElicitRequestParams& params) {
    ElicitResult result;
    result.action = "accept";
    result.content = JsonValue::Object{{"confirmed", true}};
    return result;
});
```

The handler can also be supplied through `ClientOptions`:

```cpp
ClientOptions options;
options.url_elicitation_handler = [](const ElicitRequestParams&) {
    ElicitResult result;
    result.action = "decline";
    return result;
};
```

### Impact

- The handler must return `accept`, `decline`, or `cancel`; any other value throws `McpError(McpErrorCode::HandlerError)`.
- With no handler the default is `decline`, not `accept`.
- If the old void behavior is really needed, use the deprecated `SetLegacyUrlElicitationHandler`; it fixes the action to `accept` and does not expose the three-state result. 0.3.10 will not add an old-signature overload.
- The legacy era still sends `notifications/elicitation/complete` after the response; the modern era completes through MRTR `inputResponses`.

## 5. `McpServer::GetCapabilities()` returns by value

### Old form

```cpp
const ServerCapabilities& caps = server->GetCapabilities();
auto& mutable_caps = server->GetCapabilities(); // Does not compile in 0.3.9
```

### New form

```cpp
ServerCapabilities caps = server->GetCapabilities();
const auto snapshot = server->GetCapabilities();
```

### Impact

- The return type changed from `const ServerCapabilities&` to `ServerCapabilities`. A `const&` binding may still compile through lifetime extension, but it binds to a temporary copy and no longer aliases `McpServer` state.
- Code that needs a reference or pointer fails to compile; hold a copy instead.
- Returning by value removes the data race risk of reading the internal `capabilities_` outside its lock; the copy is much cheaper than a protocol round-trip.

## 6. `FileRef` `offset` / `length` are strictly int64

### Old form

```cpp
// 0.3.8: non-numbers were ignored and doubles were truncated.
FileRef ref = DeserializeFileRef(json);
```

### New form

```cpp
JsonValue json(JsonValue::object_tag);
json["uri"] = "file:///data.bin";
json["offset"] = int64_t{1024};
json["length"] = int64_t{4096};
FileRef ref = DeserializeFileRef(json);
```

### Impact

- `offset` / `length` must be a JSON integer or an integral JSON double such as `1024.0`. Fractions, NaN, infinity, values outside int64 range, and strings/booleans/null throw `McpError(McpErrorCode::DeserializeFailed)`.
- 0.3.8 silently kept the default 0 for non-numbers and truncated doubles; code relying on that lax behavior must sanitize the JSON before calling.
- Serialization is unchanged: zero `offset` / `length` are omitted, non-zero values are written as `int64_t`.

## 7. Additional items

### 7.1 `CompleteRequestParams::context_arguments`

0.3.9 adds `context_arguments`, serialized as `context.arguments` only when non-empty:

```cpp
CompleteRequestParams params;
params.ref = JsonValue::Object{{"type", "ref/prompt"}, {"name", "weather"}};
params.argument_name = "city";
params.argument_value = "Shanghai";
params.context_arguments = {{"locale", "en-US"}, {"unit", "metric"}};
```

Impact: the old four-field aggregate initialization (`{ref, name, value, meta}`) passes `meta` to `context_arguments` and fails to compile; use member assignment. Deserialization requires `context.arguments` to be an object whose values are strings.

### 7.2 `TaskState::owner` and new `IMcpTaskStore` virtuals

`TaskState` adds `owner` after `task_id`, so old aggregate initialization fails:

```cpp
TaskState state;
state.task_id = "task-1";
state.owner = server.SessionId();
state.status = TaskStatus::Pending;
```

`IMcpTaskStore` adds the following virtuals, all with default implementations, so existing custom stores keep compiling:

- `CreateTask(task_id, owner, ttl_ms)`: defaults to `CreateTask(task_id)` followed by `SetTaskOwner` / `SetTaskTtl`.
- `FailTask`, `RemoveTask`, `GetExpiredTaskIds`, `SetTaskOwner`, `SetTaskTtl`.

Impact: the server uses `owner` for session isolation; an empty owner is treated as legacy data and remains accessible. Custom stores that want TTL cleanup and session isolation should override these functions. `FileTaskStore` implements all of them.

### 7.3 `ClientOptions` handler fields and new options

0.3.9 moves handler configuration into `ClientOptions` and adds several options:

```cpp
ClientOptions options;
options.elicitation_handler = [](const ElicitRequestParams&) {
    ElicitResult result;
    result.action = "accept";
    return result;
};
options.url_elicitation_handler = options.elicitation_handler;
options.sampling_handler = [](const CreateMessageRequestParams&) {
    return CreateMessageResult{};
};
options.roots_handler = [](const ListRootsRequestParams&) {
    return ListRootsResult{};
};
options.enable_etag_cache = true;
options.cache_auth_context = [] { return std::string("tenant-a"); };
options.on_transport_close = [] {};
options.on_transport_error = [](std::string_view message) {};
```

Impact: the new fields sit between `capabilities` and `connect_mode`, so old `ClientOptions{client_info, capabilities, connect_mode}` aggregate initialization fails to compile; use member assignment. `DeriveClientCapabilities` advertises elicitation, sampling, and roots capabilities from the configured handlers and fills only the parts that an explicit `capabilities` value leaves out.

### 7.4 `OAuthClientOptions` new field and OAuth hardening

New field:

```cpp
OAuthClientOptions oauth;
oauth.allowed_authorization_server_origins = {"https://auth.example.com"};
```

Impact:

- The field sits between `client_assertion_clock_seconds` and the callback fields; full aggregate initialization must be adjusted, and member assignment is preferred.
- Authorization-server endpoints must use https (loopback is exempt); a cross-origin authorization server must be same-origin with `server_url` or listed in `allowed_authorization_server_origins`.
- `OAuthClientProvider::IsSecureEndpoint` / `IsSameOrigin` expose the same checks.
- Issuer anchoring is persisted through `ITokenCache::StoreBoundIssuer` / `GetBoundIssuer`; a custom cache still compiles without overriding them but will not retain the anchor across instances.

### 7.5 `StreamableHttpServerOptions::listen_hold_open`

The 0.3.8 and 0.3.9 headers both contain `listen_hold_open`; it was not changed in 0.3.9 and still defaults to `false`. It controls whether the HTTP response for `subscriptions/listen` is held open. It is not a 0.3.9 migration item and existing configuration needs no change.

### 7.6 Other new interface virtuals

All of these have default implementations, so existing derived classes compile unchanged; override them only when the new behavior is needed.

- `ITransport::RequiresRequestScopedNotifications()`: defaults to `false`; `StreamableHttpServerTransport` returns `true`. Override in a custom transport that needs request-scoped notification streams.
- `ITokenCache::StoreBoundIssuer` / `GetBoundIssuer`: default no-op / `std::nullopt`; `InMemoryTokenCache` and `FileTokenCache` implement them.
- `WireCodec::ValidateRequest` / `ValidateNotification` overloads taking `WireMessageView`: default to forwarding to the `JsonValue` overloads; `MakeWireRequestView` / `MakeWireNotificationView` are new.
- `IMcpTaskStore` owner/TTL/expiry virtuals are covered in 7.2.

## 8. Other public-header changes in 0.3.9

These are mostly additions and usually need no migration, but they are visible in public headers:

| Change | Notes |
| --- | --- |
| `McpClient::SendRequest` / `SendNotification` / `CancelRequest` / `SetLoggingLevel` | New generic request and control entry points; `SetLoggingLevel` is legacy-only |
| `McpServer::IsRunning()` / `SessionId()` | New running state and server session identifier |
| `McpSessionHandler::SendRequest(..., OutcomeCallback)` | New overload with result/error outcome callback |
| `McpSessionHandler::SetServerInfo` | Lets the session layer inject `serverInfo` |
| `IncomingRequestMeta` `RequestOutcome` / `OutcomeCallback` | New result/`ErrorData` discriminated types |
| `PendingRequest` gains `outcome_callback`, `method`, `request_id` | Old aggregate initialization must switch to member assignment |
| `RequestContext` constructor gains a defaulted parameter | Source-compatible; modern `Log` can be gated by per-request `logLevel` |
| `detail::WriteAtomicSecure` / `detail::WriteWholeMessage` | New internal helpers used by `FileTaskStore` / `FileTokenCache` |

## Migration checklist

- [ ] Every `ResourceLink` has a non-empty `name`, with metadata filled in as needed.
- [ ] `ClientOptions::enable_apps_extension` assignments are removed.
- [ ] `ServerOptions::InputRequiredConfig::legacy_shim`, `ServerOptions::enable_dpop`, and `ServerOptions::enable_interceptor_alias` assignments are removed.
- [ ] Void URL elicitation callbacks return `ElicitResult`, or temporarily use `SetLegacyUrlElicitationHandler`.
- [ ] `GetCapabilities()` references/pointers are replaced with value copies.
- [ ] `FileRef` `offset` / `length` come from integral JSON values.
- [ ] `ClientOptions`, `TaskState`, and `CompleteRequestParams` aggregate initialization still compiles; prefer member assignment.
- [ ] Run `cmake --build --preset debug --target mcp-compat-smoke` and confirm there are no compile failures outside the allowlist.
