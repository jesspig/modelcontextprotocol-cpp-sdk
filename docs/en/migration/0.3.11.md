# 0.3.11 Release Notes

> **Status**: 0.3.11 released. `mcp::kSdkVersion` in `include/mcp/McpVersion.hpp` is `"0.3.11"`, and every signature, default value, and limit on this page was checked against the public headers of that release.

0.3.11 is a **patch** release centered on making existing contracts explicit and hardening transport and protocol boundaries: public headers gain `[[nodiscard]]`, compile-time precondition assertions, and debug-time invariants; HTTP/SSE, the protocol engine, the task store, and the network stack fix a batch of concurrency and boundary defects; compatibility classes and a deprecation registry are used for the first time (see the [deprecation registry](/en/learn/compatibility)).

## Compatibility classes

Every change is assigned to one of the three classes defined by the compatibility constitution:

- **Class A (fully compatible)**: implementation only; public signatures and wire behavior are unchanged. Most fixes in this release are class A.
- **Class B (source compatible, stricter behavior)**: same signatures, stricter runtime or wire behavior. This release covers duplicate critical request headers, the cumulative header budget, the event replay cap, the response queue cap, the `listen` entry cap with expiry eviction, and no longer sending `-32002` in the modern era.
- **Class C (source compatible, new compile diagnostics)**: new `[[nodiscard]]` annotations, compile-time `static_assert` preconditions, and debug-time invariant assertions.

## New and changed

- **Contract attributes**: `[[nodiscard]]` is added to return values across `JsonValue`, `JsonRpc`, `Transport`, `CancelToken`, `ProtocolVersion`, `ClientOptions`, `McpClient`, `OAuthClientProvider`, `TokenCache`, `SkillVerify`, and `VersionNegotiation`.
- **Compile-time preconditions**: `ProtocolVersion.hpp` asserts that the version table stays strictly ascending and that the modern threshold is self-consistent; `Limits.hpp` asserts the size relationships between stdio frames, SSE events, HTTP bodies, DCR payloads, and channel capacity.
- **Debug-time invariants**: `MessageChannel`, `SessionStore`, `EventStore`, `StreamableHttpServerTransport`, `McpSessionHandler`, and `WireCodec` assert queue, capacity, and encoding preconditions in debug builds.
- **Configurable limits**: the protocol engine response queue capacity can be adjusted with `SetResponseQueueCapacity()` (default 1024); the HTTP server gains `request_timeout`; SSE replay gains `max_sse_replay_bytes`.
- **Authentication**: the OAuth client validates the issuer of the authorization response per RFC 9207 (`authorization_response_iss_parameter_supported`), keeping a compatibility window for servers that do not send `iss` yet.
- **Event store**: `Append` now uses a sidecar cursor file for O(1) appends.
- **Build**: a clang-tidy baseline configuration and address/thread sanitizer switches are added; `-Werror` no longer propagates to consumers.

## Behavior fixes

- **HTTP server**: duplicate critical request headers are rejected; header reads use a cumulative budget (64 KiB / 100 headers); slow SSE clients no longer block broadcasts; event replay gains count and byte caps and no longer truncates frame separators at the cap; `Stop()` no longer cross-waits on its own connection threads; the request timeout is configurable.
- **Protocol engine**: the request table is isolated per session; the response queue is capped; cancellation notifications no longer settle the local outbound request; notification callbacks go through a unified exception guard.
- **SSE client**: CRLF framing is supported; long streams are no longer truncated by the response body cap; the reconnect budget resets after a successful stream.
- **Sessions and tasks**: `listen` entries are idempotent per client id and gain a session cap with expiry eviction; task wrap-up notifies according to the store's real state; expiry sweeps skip non-terminal tasks; tasks waiting for input reject a direct result completion.
- **Network stack**: spawned processes no longer inherit parent sockets; TLS shutdown no longer waits while holding the lock; TLS uses iPAddress verification for IP literals; socket close and read/write no longer reuse a file descriptor; closing the HTTP client no longer clears the shared read buffer; sockets accepted by the HTTP server are non-blocking; the shared TLS context explicitly loads `SSL_CERT_FILE`.
- **Other**: `extensions/list` holds the shared lock while reading the registry; `tools/list` cache hints are computed per session; non-object `capabilities` throw, and Schema numeric equality plus the elicitation fallback warning are tightened.

## Deprecations and limits

- **Deprecated**: `McpErrorCode::ResourceNotFound` (`since 0.3.11, removed in 0.4.0`) — use `InvalidParams`; the modern era no longer sends `-32002`. See the [deprecation registry](/en/learn/compatibility) for the full list and replacements.
- **Limits**: the response queue defaults to 1024; request headers are capped at 64 KiB / 100 headers; SSE event and replay caps are bounded by `kMaxMessageSize` (replay defaults to the per-event cap); `listen` entries have a session cap and expiry; `Elicit` waits are bounded by the `input_required_config` rounds and timeouts.

## Upgrading from 0.3.10

- **Class A needs no changes**: rebuild after upgrading.
- **Class C**: if a `[[nodiscard]]` result is intentionally ignored, write `(void)call;`; a failing `static_assert` means a compile-time capacity precondition is violated — adjust the configuration constants instead of deleting the assertion.
- **Class B**: check each row below for the old behavior, the new behavior, and what to change.

| Item | Old behavior | New behavior | What to change |
|---|---|---|---|
| Duplicate critical headers | accepted, later value may win | rejected | de-duplicate on the sender; keep a single `Host`, `Content-Length`, and similar |
| Header reads | unbounded single read | cumulative budget of 64 KiB / 100 headers | trim headers or split the request |
| Event replay | no count or byte cap | bounded by `max_sse_replay_bytes` and a count cap | replay less after `Last-Event-ID`, or raise the cap |
| Response queue | unbounded | default 1024; over-cap responses are rejected | use `SetResponseQueueCapacity()`, or drain faster |
| `listen` entries | unbounded and non-idempotent | idempotent per client id, with a session cap and expiry eviction | reuse client ids, or raise the cap |
| modern-era `-32002` | may be sent or received | not sent; use `-32602 InvalidParams` | handle `InvalidParams` on the receiving side; send `InvalidParams` |

## Verification and release wrap-up

- **Test baseline**: 18 test targets / 1019 registered `ctest` cases on Windows / 1030 static cases / 4873 static assertions (`MCP_WITH_OPENSSL=AUTO` with OpenSSL not found on the measuring host).
- **CI**: all 14 CI jobs pass on develop `53db38f`, covering ASan+UBSan, TSan, install consumer, compat smoke, examples, and both the OpenSSL 3 and OpenSSL 4 matrices; Conformance and Docs Validate pass on the same commit.
- **Platform fixes**: the macOS slow-SSE case and the Windows debug TLS case were diagnosed and fixed in this release (non-blocking accepted sockets and the shared TLS context explicitly loading `SSL_CERT_FILE`), and are covered by that CI run.
- **Not covered here**: this page does not cover the 0.4.0 removals; `ResourceNotFound` is removed in 0.4.0, and the [deprecation registry](/en/learn/compatibility) must be updated then.
