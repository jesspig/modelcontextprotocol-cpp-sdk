# 0.3.12 Release Notes

> **Status**: 0.3.12 released. `mcp::kSdkVersion` in `include/mcp/McpVersion.hpp` is `"0.3.12"`, and every new interface, default, and limit on this page was checked against the public headers of that release.

0.3.12 is a **patch** release centered on high-level client read APIs, hardened OAuth discovery fallback, client reliability, and a helper for legacy errors. This release is **entirely source-compatible** — it introduces no breaking changes and no new compiler warnings; the deprecation registry (see the [deprecation registry](/en/learn/compatibility)) is byte-for-byte identical to the previous release.

## Compatibility classes

Per the compatibility constitution, this release classifies as follows:

- **Class A (fully compatible)**: internal implementation or defect fixes only; public signatures and wire behavior unchanged. The OAuth fallback switch (default `true`), subscription close cancellation, and Pin-mode assignment fix are Class A.
- **New APIs (source-compatible)**: `ReadSkill`, `ReadSkillDirectory`, and `ParseUrlElicitationRequired` are new symbols; existing call sites are unaffected.
- This release has **no Class B (behavior tightening) or Class C (new compiler warnings)** changes.

## Additions and changes

- **High-level Skills reads**: `McpClient` gains `ReadSkill(uri, options?)` and `ReadSkillDirectory(uri, options?)`, performing manifest fetch, per-file download, and size/digest/frontmatter validation in one call and returning structured results (`SkillReadResult` / `SkillDirectoryReadResult`). The implementation reuses the `SkillVerify` primitives and the existing pagination/cache policy; `ListSkills` / `GetSkill` / `ReadDirectory` behavior is unchanged. Validation failures are recorded in `diagnostics[].uri/reason` (`size_mismatch`, `digest_mismatch`, `frontmatter_mismatch`) without throwing; network and protocol errors still propagate as `McpError`.
- **OAuth discovery fallback switch**: `OAuthClientOptions` gains `allow_legacy_metadata_fallback` (default `true`, preserving existing behavior); `OAuthMetadata::Discover` gains a defaulted `allow_legacy_fallback = true` parameter. When explicitly disabled, an unreachable PRM or empty AS metadata no longer falls back to the resource server's origin RFC 8414 document and returns empty. Issuer binding, `iss` validation, and refresh semantics are unchanged. Security-sensitive deployments may set `allow_legacy_metadata_fallback` to `false` explicitly.
- **Legacy URL elicitation parsing**: `ParseUrlElicitationRequired(const McpError&)` parses the `data.elicitations` array of a `-32042` error into an optional result holding `mode` / `elicitation_id` / `url` / `message`; a mismatched code or missing fields returns empty without throwing. This applies only to legacy `2025-11-25` negotiation (modern versions use the MRTR `InputRequiredResult`) and does not automatically retry the original request. Note the wire field `elicitationId` maps to the C++ member `elicitation_id` (repository snake_case convention).

## Behavior fixes

- **Subscription close cancellation**: a new internal `ClearPendingSubscriptionAck()` wakes waiters from `Close()` and the transport-close callback; after an independent transport close, `SubscribeAsync` returns deterministically within one polling cycle instead of waiting 5 seconds and throwing `InternalError`. The success path and error codes are unchanged, and no thread join was added.
- **Pin-mode negotiation**: removed the erroneous assignment of client info into `discover.server_info` in the `ConnectMode::Pin` branch; `DiscoverResult.server_info` stays default-empty and `GetServerInfo()` behavior is unchanged.

## Deprecations and limits

- **Deprecations**: carried over from the previous release — `ResourceNotFound` (`since 0.3.11, removed in 0.4.0`) remains replaced by `InvalidParams`; no new deprecations in this release.
- **Limits**: total bytes per skill remain under the existing cap; `ReadSkillDirectory` pagination is bounded at 64 pages, beyond which `ProtocolViolation` is thrown.

## Upgrading from 0.3.11

- **No changes required**: this release is entirely source-compatible additions and fixes — simply recompile; the new `Discover` parameter is defaulted, so existing single-argument calls are unchanged.
- **Optional adoption**: callers needing full contract validation can move to `ReadSkill` / `ReadSkillDirectory`; deployments wanting tighter discovery can set `allow_legacy_metadata_fallback` to `false` explicitly.
- **No Class B/C migration**: there are no behavior tightenings requiring an old/new comparison and no new warnings to silence with `(void)`.

## Research and tracking (no runtime impact)

- The `io.modelcontextprotocol/files` extension is still a draft (announced 2026-11-10, requires `2026-07-28+`, no official reference implementation); this release only tracks it, without implementation. `enable_file_input` is a tool-argument inlining capability and is not the same as that extension.
- The next spec version `2027-03-30` (SEP-3398, announced 2026-11-11, not yet released) and new conformance scenarios are registered for tracking in the internal protocol-tracking note.
