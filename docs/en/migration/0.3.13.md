# 0.3.13 Migration and Release Candidate Notes

> **Status**: 0.3.13 is a **release candidate**, not yet tagged. `mcp::kSdkVersion` in `include/mcp/McpVersion.hpp` is still `"0.3.12"`; the version number, tag, and release metadata are closed out by a later release task. This page describes only the public-header and behavior differences between the current candidate and released 0.3.12, and does not claim the release has shipped.

The 0.3.13 theme is a unified hardening of OAuth, Tasks, Skills, sessions, HTTP, storage, extensions, and validation boundaries. Compared with 0.3.12, no public declaration was removed, no old signature changed, and no old field semantics changed other than the documented default-value tightening. Changes are concentrated in new types/fields/overloads and 13 groups of Class B behavior tightening. Every item below lists its old behavior, new behavior, affected callers, and a complete compilable migration snippet; all snippets live in `docs/snippets/migration-0.3.13.cpp` and are syntax-checked by `mcp-docs-snippets`.

## Compatibility classes

- **Class A (internal implementation or source-compatible additions)**: no signature or existing default behavior changes. The OIDC discovery fallback candidate in `DiscoverWithPolicy`, `ext::AppsHostBridge`, `ext::FetchServerCard`, `ServerCardClientOptions`, the `SkillReadParts` overload, `CurrentNegotiationSnapshot()`, the three defaulted DPoP methods on `ITokenCache`, the optional `FileInputConfig` field, the root-namespace alias migration of HTTP callback contexts, and the WebSocket frame-header parser extraction are Class A. Class A has **no migration items**, stated explicitly below.
- **Class B (source-compatible, behavior tightening)**: old code still compiles but runtime semantics are stricter; each item needs an old/new/how-to-change comparison. There are 13 groups in this candidate, listed item by item below.
- **Class C (new compiler warnings)**: new `[[nodiscard]]` attributes appear only on **new** symbols (negotiation snapshot, skill parsing helpers, Server Card client helpers, DPoP validation, URL security helpers). No old API gained a warning attribute, so no `(void)` cleanup is needed in existing code; use `(void)` only when deliberately discarding a new symbol's result.
- **Breaking changes**: none. No public declaration was deleted, no old signature changed, and no old default was inverted without a migration path. `tests/compat/expected_breaks.txt` remains byte-for-byte at the previous release's wording, with entries only decreasing.

### OAuth metadata and resource identifier

- **Old behavior**: a missing `iss` was accepted when the AS advertised `authorization_response_iss_parameter_supported`; missing PKCE metadata still continued; an unreachable PRM fell back to RFC 8414 and hardcoded `server_url` endpoints; `resource` allowed fragment/trailing-slash normalization or scheme+host prefix matching; `OAuthMetadata::Discover(url)` defaulted its second parameter to `true`; a URL-form `client_id` allowed any `http(s)://` value.
- **New behavior**: all three defaults are strict; `resource` must match byte-for-byte; `Discover(url)` defaults the second parameter to `false` and gains an optional third parameter; a URL-form `client_id` must be HTTPS with a non-root path and no fragment/userinfo.
- **Affected callers**: clients depending on permissive AS metadata or missing `iss`; integrations treating the AS base as `resource`; deployments using `http://` CIMD URLs.

### OAuth outbound security and redirects

- **Old behavior**: unknown origins and private addresses from metadata were contacted; loopback exceptions compared only the host; cross-origin redirects were followed with only `Authorization` stripped; the DCR response secret was parsed but not used for authentication, and invalid secrets were sent as empty values.
- **New behavior**: the constructor-derived allowlist cannot be expanded by metadata; all DNS address classes are checked; the peer is re-checked after connect; every hop is revalidated and cross-origin is denied by default; the DCR secret participates in auth with `InvalidParams` on invalid values and no secret in logs or exceptions.
- **Affected callers**: local AS/loopback fixtures, cross-origin redirect flows, DCR deployments relying on an empty secret.

### Tasks single notification and principal owner

- **Old behavior**: six modern `notifications/tasks/*` were routed by session without subscription; the owner came from the session id; no `tasks/delete` existed.
- **New behavior**: modern emits/receives only `notifications/tasks` with a complete `DetailedTask` payload; clients subscribe first and may filter with `SubscriptionFilter::task_ids`; the owner comes from the authenticated principal and modern task operations fail closed without one; modern-only `tasks/delete` returns uniform `TaskNotFound` for cross-owner access; legacy notifications and owner fallback are unchanged.
- **Affected callers**: modern task clients, filtered subscribers, and HTTP server integrators.

### Skills YAML and lazy reads

- **Old behavior**: `ReadSkill` treated the blob encoded string as the body and compared size/digest against the encoded string; frontmatter was self-compared; the full manifest was expanded in one call.
- **New behavior**: raw size/SHA-256 is computed before strict Base64 decoding, and size/digest compare **decoded** bytes; documents containing `---` are parsed with rapidyaml (documents without a separator keep the old self-comparison); the `SkillReadParts` three-argument overload is added; `ResolveSkillLocalPath` rejects absolute paths, `..`, and symlink escapes; reason values `invalid_encoding` and `frontmatter_invalid` are added.
- **Affected callers**: skill authors must declare manifest size/digest over decoded bytes and provide valid YAML 1.2 Core frontmatter; zero-prefetch callers should use the new overload. The two-argument entry keeps its old behavior.

### Sessions, DELETE, and request context

- **Old behavior**: `verify` returned ok/scopes/resource only; one `mcp-session-id` could be reused by different principals; DELETE terminated a session given only its id; unknown sessions returned 404.
- **New behavior**: `AuthResult` carries `principal`; `on_authenticated` receives a complete `ServerRequestContext` after authentication and session resolution; binding a second principal to a session returns 403; DELETE authenticates and checks ownership before the store lookup, with cross-owner and unknown sessions both returning 404 `Session expired`; pending keys include the owner; logs carry only redacted summaries. Transports without `bearer_auth` **keep the old behavior**.
- **Affected callers**: servers enabling `bearer_auth` must return a principal from `verify` and call `McpServer::SetSessionPrincipal` in the callback; clients must re-initialize when changing identity.

### HTTP binding, framing, and AutoDetect

- **Old behavior**: an empty `HttpServerOptions::bind_host` bound `INADDR_ANY`; duplicate/invalid `Content-Length` was overwritten or tolerated; each SSE path split on `\n\n` separately; 202 only logged the result even for requests; `AutoDetect` had no runtime fallback.
- **New behavior**: an empty `bind_host` binds `127.0.0.1`; checked decimal parsing and a shared incremental SSE parser are used; 202 acknowledges notifications only and requests get `-32005` immediately; `AutoDetect` closes the old session completely and falls back once to legacy SSE when the first `initialize` returns 400/404/405 with a non-JSON-RPC error body, replaying that initialize message once. Explicit `StreamableHttp`/`Sse` modes and `ConnectMode::Pin/Legacy` do not fall back.
- **Affected callers**: deployments needing wildcard bind must set `0.0.0.0` or `::`; callers relying on a 202 follow-up response must have the server return a real response; callers not wanting fallback must select a transport explicitly.
- **Migration code**:

### DPoP, caching, and negotiation snapshot

- **Old behavior**: one process-wide DPoP nonce; the issuer anchor file could be a symlink with permissive mode; only `GetAccessToken` coalesced refreshes; DPoP keys changed on restart; repeated negotiation getters could observe different snapshots.
- **New behavior**: nonces are bucketed by normalized origin + token type, with old entry points delegating to the "current bucket"; anchors reject symlinks, non-regular files, permissive modes, oversized content, and control characters; `Authenticate`, `GetAccessToken`, and `RefreshTokens` share a bounded 30s single-flight; caches implementing the DPoP extension restore validated keys across restarts; `CurrentNegotiationSnapshot()` yields one immutable snapshot.
- **Affected callers**: callers observing nonces should call `SetDPoPNonceContext` first or use the three-argument overload; callers expecting one network request per `RefreshTokens()` should inspect the refreshed token instead; custom caches do not persist by default and must override the three new methods.

### Strict JSON-RPC entry

- **Old behavior**: method+result/error, method with `id:null`, and ids that were booleans, floats, objects, or arrays were classified by field order or produced a generic deserialization error; integer `1` and string `"1"` could collide in the internal key; subscription notifications bypassed outgoing filters/spans.
- **New behavior**: all such inputs produce `McpError(InvalidRequest)`; ids are int64/string only (`null` remains valid for error responses); keys carry `i:`/`s:` tags; subscription notifications go through per-message `SendMessage` so filters, spans, and one-shot delivery apply.
- **Affected callers**: send legal envelopes with int64/string ids and no result/error alongside them; unknown-id error responses still write `null`; do not match internal key text; attach subscription auditing to the outgoing filter.

### Storage recovery and atomic writes

- **Old behavior**: corruption cleared the whole store; a truncated tail was ignored but not rewritten; a stale cursor was trusted; `WriteAtomic` was non-exclusive and followed symlinks.
- **New behavior**: a byte-identical backup is made before rebuilding from the valid prefix; a failed rebuild preserves the original file and throws `InternalError`; the tail is rewritten atomically; appends validate the cursor against the log; temporary files are created exclusively with no-follow and restricted permissions, with the parent directory flushed. Old single-object snapshots, JSONL rows, and `.meta.json` remain readable.
- **Affected callers**: callers relying on an empty store after corruption should handle `InternalError` and inspect the `.corrupt` backup; tools appending JSONL without updating the cursor should use `Append`; deployments relying on overwriting a symlink target should use a regular path. **No public API call-site change is required.**

### Server Card and FileInput

- **Old behavior**: `/server-card` returned five fixed keys with optional fields omitted; there was no ETag and the card handler wrote a duplicate CORS header; `enable_file_input=true` implicitly trusted temp/current directories with no per-call ref/byte limits.
- **New behavior**: seven keys (including `icons`) plus set optional fields are returned, with `ValidateCard` applied uniformly; a strong ETag supports weak/list/`*` `If-None-Match` matching with a 304 response; CORS is written once by `HttpServerImpl` and exposes `ETag`; an empty `file_input_config.allowed_roots` rejects every `file://`, with per-component no-follow and per-call budgets.
- **Affected callers**: old card readers can ignore unknown JSON keys; caching clients should send `If-None-Match`; file-input deployments must configure `allowed_roots` explicitly, adding the old temp/current directories to the allowlist if they need the previous behavior.

### Close/reconnect generation

- **Old behavior**: one client factory could hold several independent sessions; callbacks from an old generation kept delivering.
- **New behavior**: repeated `Connect()` closes and joins the previous generation first; old message/error/close callbacks stop after the new generation is established. WebSocket messages before 101 are queued within bounds (64 messages / 1 MiB), redirects allow only same host+port or `ws:80 → wss:443` upgrades with at most five hops; POSIX stdio environments are deduplicated by key and no longer read the parent PATH.
- **Affected callers**: create one factory per session if sessions must coexist; callers relying on unbounded pre-101 sends or cross-host redirects should use explicit legal URLs and honor bounded errors; callers relying on duplicate environment keys should set `PATH` explicitly. Constructors and `Connect()` signatures are unchanged, so there is **no migration code**.

### DiscoverWithPolicy OIDC fallback (Class A)

- **Old behavior**: the PRM-first discovery introduced by T-05 tried only `/.well-known/oauth-authorization-server`, so authorization servers publishing metadata only at `/.well-known/openid-configuration` made conformance client legs fail discovery.
- **New behavior**: the `DiscoverWithPolicy` legacy fallback adds an OIDC discovery candidate; default behavior and policy gates are unchanged — a source-compatible defect fix.
- **Affected callers**: none. No SDK code change is required; the official conformance fixture still has to allow the AS origin explicitly, inject a resolver, and pass through `iss`, which is fixture adaptation rather than a public API change. Evidence: `T-21/client-fix`.
- **Migration code**: none (Class A).

## Deprecation and expiry review

Every `[[deprecated]]` attribute in the public headers was checked against the bilingual deprecation registry: `mcp::McpErrorCode::ResourceNotFound` (since 0.3.11, removed in 0.4.0) keeps its implementation and is replaced by `InvalidParams`; `McpClient::Ping()`, `SetSamplingHandler()`, `SetRootsHandler()`, `SetLegacyUrlElicitationHandler()`, and `ServerOptions::TasksImplicitlyEnabled()` / `SkillsImplicitlyEnabled()` are protocol- or earlier-version-driven deprecations whose implementations and replacements remain. **No new deprecations and no expiry deletions in this candidate**; the at-least-one-minor window still holds. All seven registry entries match the attributes verbatim on both sides; see the [deprecation registry](/en/learn/compatibility).

## Items with no migration

The following are explicitly **no-migration items**: the OIDC fallback in `DiscoverWithPolicy`, the Apps host bridge, the Server Card client helpers, the `SkillReadParts` overload, the negotiation snapshot getter, the three defaulted DPoP cache methods, the optional `FileInputConfig` field, the callback-context namespace aliases, `CurrentNegotiationSnapshot()`, legacy storage-format readability, and the public-signature portion of close generation. Class A additions require no caller changes; the Class B items needing no code change (storage, close/reconnect) are called out above.

## Verification evidence and known limitations

- **Public API and behavior**: the itemized `git diff 0.3.12..HEAD -- include/` classification is above; no public declaration was deleted, and `tests/compat/expected_breaks.txt` remains at the previous release's 12 entries with no additions.
- **Regression baseline**: Windows clang-cl full `ctest` 1242/1242 (T-20) and 1243/1243 after the T-21 fix; WSL2/Linux clang 21 at 1266/1266 in each of ASan+UBSan, TSan, and Release (T-22).
- **Conformance / schema**: pinned referee alpha.12 with Node 22.23.3; client legacy 234/0 and modern 451/9 (nine OpenSSL environment limitations judged expected by the referee); ext-tasks v2 22/22; official JSON Schema Test Suite 405 groups / 1300 cases / 142 skipped / 2 failures (design-time fail-closed). Zero new baseline entries in all three baseline files.
- **Cross-SDK**: `@modelcontextprotocol/sdk` 1.32.2 and `mcp` 2.3.0 four-direction matrix REQUIRED 43 PASS / 0 FAIL / 6 N/A; typed Tasks are unavailable in the TS SDK (raw JSON-RPC works) and it has no `server/discover`; both are disclosed rather than hidden.

- **Toolchain limits**: snippets on this page are syntax-checked by `mcp-docs-snippets`; bilingual parity and public-symbol check exit codes are recorded in `.handoff/evidence/T-24/`. Online documentation build and in-site link checks are evidenced there as well.
